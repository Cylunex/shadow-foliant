# A 股本地选股与数据接口

## 定位

Foliant 的正式选股输入是本地 point-in-time（PIT）研究仓。问财继续并行运行一段
时间，但只保存候选交集、仅本地、仅问财和 Jaccard 指标，用于校验策略覆盖；问财
结果不参与硬门槛、评分、排序、行业配额或数据缺失降级。

所有周期均指有效交易日。60 日承担核心技术评分；120 日和 250 日只做中长期结构
与风险修正。60 日收益需要 61 个收盘点，默认至少保留 70 条缓冲；仓库引导最低 320 条、推荐 400-500 条；不足
250 条不会被统一排除，但数据完整度会下降。

## 接口限制

代码中的权威清单是 `data/source_contracts.py`，也可在登录后只读查询
`GET /api/research/source-contracts`。表中的“已公布”是供应商文档或协议硬限制；
“运行约束”是 Foliant 主动采用的保守值，不代表供应商承诺。

| 来源/接口 | 职责 | 认证 | 分页/硬限制 | Foliant 运行约束 |
| --- | --- | --- | --- | --- |
| zzshare `daily_symbol` | 单股日线 | Token | 已公布：单次 1000 条，offset 分页 | 串行，至少 1 秒间隔，最多 2 次重试 |
| zzshare `daily_market` | 全市场单日行情 | Token | 已公布：最多 10000，建议 limit=6000 | 每交易日一次主请求，串行 |
| zzshare `stk_mins` | 分钟线 | Token | 本地单次上限 1000 | 串行，至少 1 秒间隔 |
| zzshare `rt_k` | 实时报价 | Token | 已公布：20 次/分钟 | 批量代码，至少 3.1 秒间隔 |
| zzshare Fundamentals | 估值与 PIT 财务 | Token | PIT 季表必须满足 `pubDate <= trade_date` | 串行，30 秒超时，最多 2 次重试 |
| eltdx / tdx-python | 日线与分钟线独立保障 | 无 | 协议页 800；逻辑请求默认最多 3200 | 有界连接/子进程；不打印节点或响应 |
| BaoStock | 长历史与独立日线保障 | 匿名登录 | 不依赖未正式公布的稳定配额 | 单连接串行；失败熔断；不做全市场高频主源 |
| 巨潮资讯 | 法定披露公告 | 无 | 未公布稳定配额 | 串行，至少 1 秒间隔，单页 30 |
| 问财 | 外部发现与对照 | 上游会话 | 无稳定公开契约 | 串行，至少 2 秒间隔，单页、硬超时、失败不影响主链 |
| AkShare/东财个股资金排名 | 盘后真实主力资金快照 | 无 | 无稳定公开契约 | 每交易日盘后一次；只落真实净流入字段，失败不使用成交量代理 |

环境变量只允许把最小间隔调大、把并发或重试调小，不能放宽内置边界。进程内门控始终存在，Redis 可用时还会建立跨 Web/Jobs 进程的共享速率槽。命名规则是
`SOURCE_<PROVIDER>_<ENDPOINT>_MIN_INTERVAL_SECONDS/MAX_CONCURRENCY/TIMEOUT_SECONDS/RETRIES`。

## 数据同步

初始引导按交易日拉全市场快照，避免约五千只股票逐只请求：

```bash
python scripts/research_data.py bootstrap --trading-days 500
```

日常增量由 `research_data_sync` 在盘后执行，也可以手工同步指定日期：

```bash
python scripts/research_data.py sync --date 2026-01-05
```

同步结果只输出行数、覆盖率和质量状态，不输出 Token、接口响应、财务正文或证券数据。
主行情缺口只在 `RESEARCH_FALLBACK_SYMBOLS_PER_RUN` 范围内尝试精确日期的
BaoStock qfq 修补，避免逐股请求风暴。TDX 原始行情只能独立校验或报价，不能冒充
复权历史。成交量只在成交额/成交量/价格关系能验证 shares/lots 时归一化，否则标记
`unknown_unit` 并退出正式面板。旧数据不得冒充当日数据。

每条正式数据均携带或保存：`provider`、`origin`、`as_of`、`effective_at`、
`retrieved_at`、`adjustment`、`unit`、`schema_version` 和 `quality_status`。

## 选股阶段

```text
上市/非 ST/非停牌/上个完整交易日有效行情/至少 61 个收盘点
  -> 基本面与估值 TOP200（40 分）
  -> 60 日核心技术 TOP50（30 分）
  -> 行业宽度与相对强弱（15 分）
  -> 数据质量与治理（15 分）
  -> 120 日修正 [-10,+5]
  -> 250 日修正 [-10,+5]
  -> 结构化事件修正 [-25,+12]
  -> 每行业数量约束 + 60 日收益相关性去重 TOP20
  -> 本地 TOP15 -> 确定性正式 TOP5
```

60 日层包含相对市场/行业收益、MA60 斜率、区间位置、回撤、波动、上涨持续性以及
5/20 日成交量相对 60 日均量。120/250 日只检查均线方向、价格位置和长期扩张风险。
输出状态分为“趋势确认”“反转观察”“长期弱势反弹”“趋势观察”和“弱势”。

### 五组本地参考策略

正式 TOP15/TOP5 之外另有 `local-reference-v1` 独立产物，用同一份 PIT 快照复现原有
五组发现策略：主力资金、低价擒牛、净利增长、低估值和小市值。它们只形成参考列表与
“本地·策略名”共振标签，不进入正式分数或排序。

- 主力资金：读取盘后落库的当日真实主力净流入，按净流入降序；当日快照缺失时明确
  标为 `unavailable`，不拿成交量或成交额冒充资金流。
- 低价擒牛：股价低于 10 元、净利润同比增长至少 100%，排除 ST、创业板和科创板。
- 净利增长：深圳主板、净利润同比增长至少 10%，排除 ST、创业板和科创板。
- 低估值：`0<PE<=20`、`0<PB<=1.5`、资产负债率不高于 30%；全市场股息率覆盖
  充分时再执行“股息率至少 1%”硬条件。当前 zzshare 估值快照未提供该字段时，产物明确
  标记 `degraded` 并展示原因，不静默补值或伪造股息率。
- 小市值：总市值不高于 50 亿元、营收同比增长至少 10%、净利润同比增长至少 100%。

每组最多保存前 5 只；缺少必需财务字段的证券不会被宽松补值。`latest_selection`、Web
选股接口及综合选股通知均能看到该独立参考，字段 `reference_affects_score=false` 是固定
边界。

缺失策略分三类：硬门槛缺失直接拒绝；估值、财务或长周期等优选字段缺失扣覆盖率/
组件分；问财和文字说明等参考字段缺失不影响主结果。上个交易日不匹配、全市场覆盖率
低于阈值，或拥有至少 4/6 项基本面指标的证券比例低于阈值时，本地运行标记为
`incomplete` 且不产出候选。

行业字段缺失时不伪造行业分：该股票的行业组件记 0，集中度约束透明降级为证券代码
对应的市场板块桶（沪市主板、深市主板、创业板、科创板、北交所），并在运行元数据中
记录 `industry_with_board_fallback` 与行业覆盖率。已知行业仍优先按真实行业限额；候选间
最近 60 个交易日收益相关系数达到配置阈值时，后排序候选被去重。行业宽度综合行业内
60 日上涨、站上 MA60、MA60 斜率为正、接近 60 日高点和量能参与度，不再只看行业中位收益。

## 事件修正

巨潮公告标题只进入待确认线索。取得正文后，稳定文档 ID、原始/标准化数值、重大性、
意外度、新颖度、实体影响和来源字段完整的确认事件才能入库评分。负面事件上限绝对值
大于正面催化；监管、造假等风险半衰期长于普通公告。模型文本本身不直接成为选股分数。

## 迁移观察

`selection_runs` 与 `selection_candidates` 同时保存 `primary` 和
`wencai_reference`。观察期重点检查：本地仓覆盖率、TOP15 稳定性、行业集中度、
问财交集/差集、确定性 TOP5、Agent 独立复核、后验收益与最大回撤。Agent、盘中报价与
当前持仓不会改变正式 TOP5。即使问财短期表现更好，也必须先分析因子与数据
时点，不得直接恢复“命中次数即加分”。
