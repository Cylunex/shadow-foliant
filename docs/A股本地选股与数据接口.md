# A 股本地选股与数据接口

## 定位

Foliant 的正式选股输入是本地 point-in-time（PIT）研究仓。`local-fusion-v2` 在同一份
统一可投资快照上运行 PIT 综合核心、本地五策略和技术基因组三路本地生产器。问财、
妙想和 Agent 只保存外部参考或复核事实，不参与硬门槛、成员、评分、排序或数据缺失降级。

所有周期均指有效交易日。60 日承担核心技术评分；120 日和 250 日只做中长期结构
与风险修正。60 日收益需要 61 个收盘点，默认至少保留 70 条缓冲；仓库引导最低 320 条、推荐 400-500 条；不足
250 条不会被统一排除，但数据完整度会下降。

## 接口限制

代码中的权威清单是 `data/source_contracts.py`，也可在登录后只读查询
`GET /api/research/source-contracts`。表中的“已公布”是供应商文档或协议硬限制；
“运行约束”是 Foliant 主动采用的保守值，不代表供应商承诺。

| 来源/接口 | 职责 | 认证 | 分页/硬限制 | Foliant 运行约束 |
| --- | --- | --- | --- | --- |
| zzshare `daily_symbol` | 单股日线 | Token | 已公布：单次 1000 条，offset 分页 | 串行，至少 1 秒间隔，最多 2 次重试 |
| zzshare `daily_market` | 全市场单日行情 | Token | 已公布：最多 10000，建议 limit=6000 | 每交易日一次主请求，串行 |
| zzshare `stk_mins` | 分钟线 | Token | 本地单次上限 1000 | 串行，至少 1 秒间隔 |
| zzshare `rt_k` | 实时报价 | Token | 已公布：20 次/分钟 | 批量代码，至少 3.1 秒间隔 |
| zzshare Fundamentals | 估值与 PIT 财务 | Token | PIT 季表必须满足 `pubDate <= trade_date` | 串行，30 秒超时，最多 2 次重试 |
| eltdx / tdx-python | 日线与分钟线独立保障 | 无 | 协议页 800；逻辑请求默认最多 3200 | 有界连接/子进程；不打印节点或响应 |
| BaoStock | 长历史与独立日线保障 | 匿名登录 | 已公布：每日最多 50000 次，不可并发连接访问 | Web/Jobs/Agent 跨进程单通道；默认 45000 次硬停；失败熔断 |
| 巨潮资讯 | 法定披露公告 | 无 | 未公布稳定配额 | 串行，至少 1 秒间隔，单页 30 |
| 问财 | 外部发现与对照 | 上游会话 | 无稳定公开契约 | 串行，至少 2 秒间隔，单页、硬超时、失败不影响主链 |
| AkShare/东财个股资金排名 | 盘后真实主力资金快照 | 无 | 无稳定公开契约 | 每交易日盘后一次；只落真实净流入字段，失败不使用成交量代理 |

环境变量只允许把最小间隔调大、把并发或重试调小，不能放宽内置边界。进程内门控始终存在，Redis 可用时还会建立跨 Web/Jobs 进程的共享速率槽。命名规则是
`SOURCE_<PROVIDER>_<ENDPOINT>_MIN_INTERVAL_SECONDS/MAX_CONCURRENCY/TIMEOUT_SECONDS/RETRIES`。

## 数据同步

初始引导按交易日拉全市场快照，避免约五千只股票逐只请求：

```bash
python scripts/research_data.py bootstrap --trading-days 500
```

日常增量由 `research_data_sync` 在盘后执行，也可以手工同步指定日期：

```bash
python scripts/research_data.py sync --date 2026-01-05
```

同步结果只输出行数、覆盖率和质量状态，不输出 Token、接口响应、财务正文或证券数据。
主行情缺口只在 `RESEARCH_FALLBACK_SYMBOLS_PER_RUN` 范围内尝试精确日期的
BaoStock qfq 修补，避免逐股请求风暴。BaoStock 请求数按自然日持久化到共享
运行目录；日预算可用 `BAOSTOCK_DAILY_REQUEST_BUDGET` 调低，但程序永远不允许超过
50000。TDX 原始行情只能独立校验或报价，不能冒充
复权历史。成交量只在成交额/成交量/价格关系能验证 shares/lots 时归一化，否则标记
`unknown_unit` 并退出正式面板。旧数据不得冒充当日数据。

每条正式数据均携带或保存：`provider`、`origin`、`as_of`、`effective_at`、
`retrieved_at`、`adjustment`、`unit`、`schema_version` 和 `quality_status`。

证券主数据分别请求 `L`（在市）、`D`（退市）和 `P`（暂停上市）。程序不会把“请求返回
HTTP 成功”当成状态可信：只有供应商状态字段与请求相符，或退市日期能证明 `D` 状态时才
接纳；至少 `L/D` 完整后才能发布新快照。历史研究允许用后来观测到的上市/退市日期重建当时
成员，但会明确标记行业字段不是历史 PIT 行业，不用当前行业标签冒充历史暴露。

## 选股阶段

```text
上市/非 ST/非停牌/上个完整交易日有效行情/至少 61 个收盘点
  -> 基本面与估值 TOP200（40 分）
  -> 60 日核心技术 TOP50（30 分）
  -> 行业宽度与相对强弱（15 分）
  -> 数据质量与治理（15 分可信度权重；进入总分，但不解释为收益 Alpha）
  -> 120 日修正 [-10,+5]
  -> 250 日修正 [-10,+5]
  -> 结构化事件修正 [-25,+12]
  -> 每行业最多 5 只 + 60 日收益相关性去重，形成 PIT 核心提名
  -> 与本地五策略、技术基因组提名去重编排
  -> local-fusion-v2 TOP15 -> 在完整 TOP15 内独立确定性复排 TOP5
```

60 日层包含剔除市场 Beta 和行业共同波动后的残差趋势、MA60 斜率、回撤、特质波动、
上涨持续性以及 5/20 日成交额相对 60 日均额。120/250 日只检查均线方向、价格位置和
长期扩张风险。
输出状态分为“趋势确认”“反转观察”“长期弱势反弹”“趋势观察”和“弱势”。

生产评分与研究报告共同引用版本化特征目录 `selection-features-v1`。当前固定预算为：

| 评分族 | 分值 | 核心内容 |
| --- | ---: | --- |
| 基本面与估值 | 40 | 盈利质量 10、成长质量 8、资产负债 6、现金流 6、估值 10 |
| 60 日技术结构 | 30 | 市场/行业残差趋势 13、趋势持续 7、回撤与特质风险 6、彩票特征 2、量能 2 |
| 行业结构 | 15 | 广度、MA60、斜率、高位参与、量能参与、行业收益 |
| 数据质量 | 15 | 覆盖与可信度，不解释成收益 Alpha |

研究可以提出下一版目录，但不能直接修改当前生产权重；正式运行和回放均保存目录版本。

### 五组本地真实候选策略

`local-satellite-v3` 在统一硬门槛之后运行五组本地策略：主力资金、低价擒牛、低估值、
小市值和净利增长。每组最多提名 5 只；提名分只在各自策略内部比较，不与 PIT 或基因组
分数相加。去重后共同争取正式 TOP15 最多 5 个卫星名额，TOP5 最多 1 个名额。

生产优先级固定为：

```text
主力资金 = 低价擒牛 = 低估值 > 小市值 > 净利增长
```

- 主力资金：读取盘后落库的当日真实主力净流入，并要求最近最多 5 个交易日多数为正流入，按持续性、流入强度、基本面和趋势排序；当日快照缺失时明确
  标为 `unavailable`，不拿成交量或成交额冒充资金流。
- 低价擒牛：股价严格低于 20 元、净利润同比增长至少 100%；字段可用时再要求利润为正、营收不下降、经营现金质量合格且最近三期至少两期正增长，然后按增长、现金质量、估值、趋势、回撤和流动性排序。它保留为独立正式策略族。
- 净利增长：沪深主板、净利润同比增长至少 10%，按增长持续性、财务质量和趋势排序；生产优先级最低。
- 低估值：`0<PE<=20`、`0<PB<=1.5`；非金融行业资产负债率不高于 65%，金融行业改为同行比较；全市场股息率覆盖
  充分时再执行“股息率至少 1%”硬条件。当前 zzshare 估值快照未提供该字段时，产物明确
  标记 `degraded` 并展示原因，不静默补值或伪造股息率。
- 小市值：排除全市场市值最小 20%，总市值不高于 50 亿元、营收同比增长至少 10%、净利润同比增长至少 100%，并加入质量、趋势和流动性约束。

小市值与净利增长属于同一个成长小盘策略族；同一股票同时命中两者时只算一次独立确认。
低价擒牛是单独策略族，不会因这项去重被降级。问财结果继续并行保存，但只用于发现和
复核，不能改变正式成员、分数或权限边界。

字段 `reference_affects_score=false` 表示“不做命中次数或跨赛道分数相加”；
`candidate_affects_membership=true` 表示这些本地提名会通过正式配额影响成员。Web、Agent
和通知会分别展示入选赛道、主要策略与共同提名。

### 技术基因组候选

技术基因组不再只扫描已有 TOP15。系统先在统一合格全集上用本地基本面、技术面和数据
覆盖率预筛最多 250 只，再使用当前已部署的进化变体做精确扫描，最多提名 5 只，正式
TOP15 最多占 2 席、TOP5 最多占 1 席。放量跌停等明确偏空策略不进入买入提名。

正式运行保存完整 `strategy_snapshot_id`、变体参数和部署统计，历史回放使用同一份部署
快照，不读取后来进化出的参数。多个相近形态同时命中只给有限的类别多样性奖励，不再把
命中权重简单累加成买入强度。

基因组研究默认从回测起点重建证券生命周期股池并确定性抽样，避免用“今日仍在市的赢家”
回放历史。生命周期不完整时固定样本仍可运行，但结果标记为探索。非默认变体进入生产必须
满足：训练分至少 50、近 14 日完成评估、样本外至少 12 次触发、胜率至少 45%、平均收益
不为负；不满足的策略继续使用固定默认参数。组合策略没有“样本外为空也先上线”的宽限。

### 正式配额

```text
TOP15：PIT 核心至少 8 / 本地五策略最多 5 / 技术基因组最多 2
TOP5 ：PIT 核心至少 3 / 本地五策略最多 1 / 技术基因组最多 1
```

卫星名额是上限而不是保底；未达到各自绝对门槛时全部归还 PIT。PIT 与其他本地策略共同
提名的股票默认占 PIT 名额，但所有 `supporting_nominations` 都会保留。同一行业最多 5 只，
合并后再次执行 60 日相关性约束。TOP5 不再复用 TOP15 的赛道穿插模板，而是在完整
TOP15 内用 PIT 综合质量、赛道内强度、数据覆盖率、策略优先级和本地共同提名做归一化
确定性复排，再执行“PIT 核心至少 3、本地五策略最多 1、技术基因组最多 1”的组合约束。
各赛道原始分单位不同，复排前会分别归一化，不直接跨赛道相加；问财、妙想、实时行情、
持仓和 LLM 均不进入复排。因此 TOP5 可能恰好包含 TOP15 前列，但不再结构性等于前五行。

缺失策略分三类：硬门槛缺失直接拒绝；估值、财务或长周期等优选字段缺失扣覆盖率/
组件分；问财和文字说明等参考字段缺失不影响主结果。上个交易日不匹配、全市场覆盖率
低于阈值，或拥有至少 4/6 项基本面指标的证券比例低于阈值时，本地运行标记为
`incomplete` 且不产出候选。

行业字段缺失时不伪造行业分：该股票的行业组件记 0，集中度约束透明降级为证券代码
对应的市场板块桶（沪市主板、深市主板、创业板、科创板、北交所），并在运行元数据中
记录 `industry_with_board_fallback` 与行业覆盖率。已知行业仍优先按真实行业限额；候选间
最近 60 个交易日收益相关系数达到配置阈值时，后排序候选被去重。行业宽度综合行业内
60 日上涨、站上 MA60、MA60 斜率为正、接近 60 日高点和量能参与度，不再只看行业中位收益。

## 事件修正

巨潮公告标题只进入待确认线索。取得正文后，稳定文档 ID、原始/标准化数值、重大性、
意外度、新颖度、实体影响和来源字段完整的确认事件才能入库评分。负面事件上限绝对值
大于正面催化；监管、造假等风险半衰期长于普通公告。模型文本本身不直接成为选股分数。

## 后验与策略政策进化

`selection_strategy_runs` 和 `selection_candidate_nominations` 分别保存策略运行与逐策略
提名；`selection_candidate_outcomes` 按“信号后下一交易日开盘进入”口径更新 1/3/5/10/20
交易日收益和最大回撤。`pit_only_top15` 只作后台反事实对照，不形成第二套推送或影子选股。

BaoStock 日 K 在 17:30、复权因子在 18:00 完成，因此每个交易日 18:05 才启动全市场
研究行情同步并更新确定性后验；20:05 仅在当天快照未完整时轻量补行情与估值，不重抓财务或可选主力资金，正常完成则秒级跳过。若估值提供方仍未发布，任务记为外部源跳过而非程序失败，并在次交易日 08:35 按同一 PIT 日期边界再补一次；09:45 正式选股仍保留最终自愈和 fail-closed 门禁。
18:35 的大批量 K 线预热排在正式 PIT 同步之后，且 K 线与交易日历分别熔断，避免预热争用
BaoStock 单会话或短暂失败连带封锁正式 PIT 日历校验。09:45 正式选股还会在读取前
检查上一完整交易日的同步标记；若晚间两次都因网络失败，只补一次 zzshare 全市场
行情与估值，显式禁用财务 PIT 重抓和逐股 BaoStock 修补。依赖 K 线的因子、指标和后验任务仍
由 deferred 队列等待真实完成，而不是只相信时钟间隔。问财和妙想按各自策略 ID、版本及定义/查询哈希保存为 `reference` 提名，同样计算
后验用于差异研究，但任何表现都不能直接获得正式名额。周日 21:00 的策略委员会只调用一次 LLM，模型只能提出
白名单内的配额、门槛和五策略使用权重变化；程序控制器随后检查政策版本、证据快照、成熟
样本、单周步长、优先级顺序和 PIT 核心锁。LLM 不能修改代码、因子、查询，也不能让问财
或妙想进入正式候选。通过的政策写入新版本；异常时可直接回到默认 `local-fusion-v2` 或
配置级 PIT-only 模式。

## 下游任务口径

- `unified_selection`：唯一正式生产入口；红蓝只复核正式 TOP5，失败不影响发布。
- `mx_selection_review`：10:30 运行五组妙想参考，并只诊断正式 TOP5；仅分歧时通知。
- `announcement_scan` / 研报扫描：消费当日正式 TOP15，不再读取旧 indicator 快照。
- `daily_backtest` 尾部技术扫描：正式 TOP5、TOP15 其余优先占用 100 只扫描预算，并在整批
  股票上锁定同一份基因组 live set；随后才加入持仓、热门股和龙虎榜。
- `research_data_sync`：研究行情入库成功后更新所有正式、本地策略、基因组及外部参考后验。
- Agent/MCP 与 Web：同时返回正式 TOP15/TOP5、赛道、生产策略、外部参考和复核附件；正式
  字段始终覆盖展示附件，LLM 结果不能改写成员或排名。
- 旧个人口味候选池只保留为手动实验，默认关闭，也不再作为正式主链失败时的兜底。

## 成交归因与统一动作

成交录入支持可选的 `selection_run_id`、`nomination_id`、`strategy_id` 和
`decision_signal_id`。不填时保持现有手工录入能力；填写后由服务端核对股票、选股运行、
提名策略和决策信号，任何不匹配都会阻止整批写入。业务库只保存经验证的稳定标识，后续可
按“哪个正式策略/信号带来这笔成交”做收益归因。

面向用户只输出四种动作：`加仓 / 不动 / 减仓 / 卖出`。冲突时固定优先级为：硬风控、持仓
事实、组合风险、正式信号；问财、妙想、新闻热度和 LLM 是参考或解释，不得把“不动/减仓”
改成“加仓”。同级冲突优先降低风险。通知正文可以包含用户需要的股票与动作，但运行日志
不得包含股票、持仓、成交、正文、收件地址、Webhook URL 或上游错误正文。
