# 基金研究与定投使用说明

基金模块使用同一组数据契约、收益规则和账务服务，供 WebUI、MCP 和后台任务调用。
场外申赎按实际确认净值记录；场内 ETF 的价格成交模型保持独立，不能以净值模拟冒充场内收益。

## 使用入口

| 页面入口 | 使用方式 |
| --- | --- |
| 总览 | 查看确认净值、估值日期、已确认部分收益和覆盖率，以及定投待办、周度资料变化 |
| 定投实验 | 设置策略，查看本金、闲置现金、费用、资金加权收益、时间加权收益和回撤；从实验记录重放冻结输入 |
| 选基研究 | 同类筛选、共同观测日期对比、指数估值及基金研究档案；缺必要字段不能通过筛选或评级 |
| 组合 | 查看已知与未知暴露，在市值和成本口径间切换，填写目标比例、渠道费率及现金，生成调仓预览 |
| 流水与计划 | 录入真实成交、预览批量导入、确认期初余额迁移；设置定投起始日并处理待确认事项 |

总览中的市值和浮盈只汇总有有效净值的部分。没有净值不使用成本填充，也不显示为零收益。
净值正常等待披露、来源缺失、历史不足与功能关闭分别保留状态。

## 真实流水与迁移

新账本保留账户、渠道、申请日期、净值归属日、确认日期、资金扣款/到账日期和录入时刻。
金额、费用按分，份额按万分之一记录；原始金额使用 Decimal 文本存储，旧浮点持仓表仅作为兼容投影。
申购成本包含实际费用，赎回按 FIFO 消耗持有批次。分红、红利再投、拆分、收益结转和冲正分别留痕。
直接删除或覆盖已接入账本的持仓会被拒绝。

建议使用以下流程：

1. 在流水界面填写实际成交回执，或调用 `/api/fund/ledger/preview`，传入 `rows`。
2. 核对预览中的账户、份额、成本及跳过的重复交易。
3. 使用同一批输入和预览返回的 `version`，向 `/api/fund/ledger/commit` 传 `expected_version`。
4. 账本发生相关变化或输入被修改时重新预览。整批校验、持仓重建、唯一键写入在同一事务中完成。

例如，匿名成交可写为：

```json
{
  "code": "000001",
  "account": "example",
  "channel": "example",
  "external_id": "example-receipt-001",
  "txn_type": "申购",
  "nav": 1.0,
  "amount": 101.0,
  "fee": 1.0,
  "application_date": "2026-10-12",
  "nav_date": "2026-10-12",
  "confirmation_date": "2026-10-13",
  "settlement_date": "2026-10-12"
}
```

此例只是字段说明，不是当前持仓或买入建议。金额和实际份额同时提供时必须能够对账。
外部交易 ID 按账户与渠道隔离；没有外部 ID 时使用规范内容指纹，同日不同成交不会按基金代码被合并。
`skip_existing` 旧参数不再关闭幂等保护。

已有持仓首次接入时保存真实的期初余额与观察日期。早于期初日期的流水须通过
`/migration/preview` 和 `/migration/commit` 提供可核验期初余额后重建。
迁移前余额、迁移记录和原流水都会保留；旧 `dca_auto` 记录仍需核验，不自动删除或认定为真实成交。
期初余额日期不等于原始购买日期，缺实际持有日期的批次不能给出确定的赎回费估计。

## 定投计划与回测

计划使用明确的起始日、周期与交易日历。双周按起始周锚定，假期顺延至有证据的开放日；
回测结束在月中时不会提前执行月末计划。旧计划缺起始日时显示待核验，可在计划列表补充；
已经生成事项的规则冻结，后续调整采用停用旧计划、新建后续计划的方式。

境内日历复用已持久化的双来源一致证据，日历缺口不会被当作休市。
QDII 等特殊产品可配置自己的 `calendar_id` 和已核验 `open_dates`，不默认套用 A 股日历。
到期仅生成待确认事项；实际成交导入时通过 `occurrence_id` 关联，支持部分确认、撤销、失败和冲正恢复。
原 `auto_record` 字段保留兼容，其行为统一为生成待办，不增加真实持仓。

回测策略包括固定金额、价格位置、真实估值和价值平均法。价格位置使用之前观察日的数据；
真实估值必须提供 `known_at` 和 `percentile`，不会用净值分位冒充估值。
用户输入的可知时间作为实验假设保存，不自动成为独立核实的历史 PIT 证据。

回测可显式提供产品 `open_dates`；未提供时会注明“净值观察日作为可申购日”的研究假设，成交可行性保持未核实。
已提供日历但执行日缺净值时返回部分数据，不挪用相邻日期净值。
回测共享资金到达计划，未投入资金保留为现金，价值平均法受到总预算和单期上限约束。
回撤从剔除外部本金流入影响的组合净值计算，另列全额本金期初可用的一次性买入情景。
分红在除息时形成应收，实际支付后才可用于现金或再投；没有支付日期的应收不被当作可用资金。
赎回费支持按批次持有天数分档；净值中已经扣除的管理费等运作费用不会再次扣除。

每次实验保存输入、数据版本、费用、日历与预算配置、质量报告和结果；失败和不支持的实验也留记录。
重放不会重新抓取行情。没有冻结输入的失败记录明确返回 `no_input_recorded`。
XIRR 对短于 30 天、无根或存在多次符号变化的现金流返回不可计算，不任意选择一个根。

## 研究与组合边界

长期评级要求至少一年跨度和 200 个观测，使用分类模型及可见权重。
指数/QDII 还需要适用的同币种基准；可配置 `benchmark_kind=fund_total_return`、基准基金代码、
`currency` 和 `benchmark_currency`，由同一数据契约获取总回报对照。
货币基金单独展示万份收益、七日年化和收益结转，不能将万份收益解析为普通单位净值。
货币基金接口的字段依据 [AKShare 官方说明](https://akshare.akfamily.xyz/data/fund/fund_public.html)。

基金档案保留观察时点、来源、经理与其他字段变化、失效条件和复核事项。
AI 输出作为解释层，不能提高数据质量、补造未知事实或更改账务。相同上下文的单次 AI 解释可缓存。
后台在既有晚间任务内按预算逐只进行周度资料复核，同基金同周完成后不重复抓取；失败保持待重试。

组合按资产、行业、地域、币种、经理及基金家族汇总，缺资料的部分显示未知。
季报穿透仅代表已披露部分，包含报告期、首次观察时点及未知暴露；不把前十大持仓当成全量资产。
直持股票和基金的重复账本条目需要核对身份，含成本回退的股票快照不进入确认市值。
目标配置与再平衡只产生预览；费率、交易状态、实际批次持有期或估值不够时列出不可执行原因。

外部通知继续受现有通知策略控制，不为基金待办或周检结果绕过安静策略。
待办和资料变化在页面保留；长正文与重复调用测试使用真实渲染内容，不发送真实测试通知。

## Agent 和接口

MCP 保留原基金查询，并增加 `fund_transaction_preview`、`fund_transaction_commit`、
`fund_research_context`、`fund_rebalance_preview`、`fund_experiment_replay` 和 `fund_migration_preview`。
原定投回测也保存实验，HTTP 与 MCP 使用相同应用服务和收益契约。

新增 HTTP 入口包括 `/workspace`、`/ledger/positions`、`/ledger/preview`、`/ledger/commit`、
`/migration/preview`、`/migration/commit`、`/research/{code}`、`/profiles/{code}`、
`/rebalance-preview`、`/targets`、`/share-class-costs`、`/account-performance`、
`/plan/{id}/settings`、`/occurrences/{id}/status` 与 `/experiments/{id}/replay`，
均位于 `/api/fund` 下，沿用现有鉴权。

A/C 类费用比较是未来持有期的静态情景，要求同一已核实基金家族和完整费率，
不再次扣减历史净值。完整账户收益接口使用日初外部转入、日末外部转出的约定，
其独立算例依据 [Portfolio Performance 的 TTWROR 说明](https://help.portfolio-performance.info/en/concepts/performance/time-weighted/)。

## 本地验证与上线验收

数据库迁移来源为 `scripts/migrations/22-fund-research-upgrade.sql`，运行期与标准迁移共享这一个来源。
生产仍只支持 PostgreSQL；SQLite 用于显式注入的离线测试。
`scripts/check_fund_upgrade.py` 默认只描述检查方式，不连接数据库；显式 `--check` 只读核查迁移和旧自动记录。
生产操作须按父目录运维约定进行，本轮未执行生产迁移或部署。

验证覆盖真实 PostgreSQL 临时实例、并发幂等、原子失败、历史重建、费用批次、部分确认与冲正、
资金流中性回撤、分红与应收、日历顺延、跨入口一致、同类评分、资料变化、实验重放和安静通知策略。
页面使用匿名样例验证五个入口，控制台未观察到渲染错误。

2026-10-15 的公开接口短样本冻结于 `tests/fixtures/fund_public_snapshots_2026-10-15.json`，
每只只保留最新两个观测和来源总量。它用于验证字段、产品分类和截断门禁，不能证明全历史完整或独立行情一致。
现金流对照另使用官方 TTWROR 算例，分红、拆分、费用和执行状态使用可手工重算的固定样例。

本地代码通过不代表生产就绪或自然业务验收。部署版本、实际数据补齐、成交确认和自然披露结果
分别记录；没有发生的事件保持未观察，不制造交易或重复投递用于验收。

本轮验证结果：全量回归 1030 项通过、12 项跳过、7 个 subtests 通过；最后一次基金专项及已有日收益回归 72 项通过。
实验还绑定计算代码哈希；规则变化时保留原结果并拒绝静默使用新规则重放。
