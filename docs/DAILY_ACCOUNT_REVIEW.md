# 每日账户复盘与计划可用性

`scheduled-agent-snapshot-v1` 增加 `daily_review`（`daily-account-review-v1`）。
它使用本次已加载的持仓与行情，以及当日盘中监控记录，不请求第二批行情、不读取其他
账户、不补跑后验、不改正式排名、不写交易或通知。

每日复盘不依赖20:45任务。只有一部分行情可用时逐项输出，整体保留 `partial`；缺成本
不计算浮盈亏，缺成交不输出已实现利润，持仓读取失败不能显示为已确认空仓。
未知交易日仍不能用于可执行判断，明确休市返回 `not_applicable`。

当日日内 `trigger_state` 的检测记录与同日有效持仓动作保留原始时间。`last_alerted_at`
是监控检测记录，不证明通知已被接受或交易已成交。最后一次报价恢复、动作受保护或新
计划止损下降，都不能抹去这些记录；盘后报告使用观察措辞，不恢复受保护的卖出动作。
过往交易日、未来时间和已不在当前持仓中的标的不会被引入当日操作观察。

`holdings_review` 用于收盘与新参考阈值的比较，`next_session_plan` 读取当日收盘重建计划。
失效计划只在 `historical_reference_plan` 中保留；不能进入新的入场区间、止损、止盈或动作
字段。正式选股缺失时仍可单独重建持仓计划，但必须有当日收盘缓存证据，并按证券、数量
和成本的规范化指纹绑定当前持仓。持仓变化后旧批次不能继续作为该账户的新计划。

已知股票价格采用现有股票规则的小数精度；其他品种的参考计划保留至少三位小数，仍需
权威品种元数据才能执行。盈亏比按实际输出的入场区间、止损和第一目标计算，保守保留
两位小数，避免低于2.0的值显示成2.00而误导判断。未核验组合环境时保持观察。
股票预算、券商可卖、价格口径、有效期及最高事件唯一发送者的门禁继续执行。

回归覆盖局部行情缺失、缺成本、过期与未来证据、保护后hold、日内触发后恢复、新旧价位
分离、持仓计划独立生成和指纹变化、基金报价精度与盈亏比边界。最大100只持仓的实际
渲染正文贯通HTTP请求模型、逻辑slot、分片、加密正文存档和重复调用；渠道用本地测试
替身，未发送真实通知。

代码测试通过不等于生产已发布。发布后应分别核验运行版本、受保护快照的每日数据覆盖、
自然定时报和存档回执；不制造最高事件或重复投递来验收。
