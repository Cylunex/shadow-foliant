# 多源估值与补跑

## 为什么日 K 齐了，估值仍可能为空

行情覆盖率与估值覆盖率是两个独立指标。zzshare 全量日 K 不包含 PE/PB；
BaoStock 的日 K 接口则可显式请求 `peTTM/pbMRQ/psTTM/pcfNcfTTM`。
估值主接口返回空集只表示没有取得目标日期数据，不能据此断言供应商尚未发布。

## 已接入的来源与口径

| 来源 | 用途 | 正式字段 / 边界 |
| --- | --- | --- |
| zzshare `finance_valuation` | 首选全市场历史快照 | PE-TTM、PB、市值等；目标日期必须相符 |
| Tushare `daily_basic` | 可选全市场历史补充 | PE-TTM、静态 PE、PB、市值、股息率；需配置 Token 且积分权限达标，每页最多 6000 行 |
| BaoStock 日 K 估值字段 | 串行历史补缺 | PE-TTM、PB-MRQ、PS-TTM；不提供市值，不支持的北交所代码不请求 |
| 腾讯 | 当日收盘快照补缺 | PB、总市值、流通市值；必须携带当日 15:00 后时间戳 |
| 麦蕊 / 魔码 | 当日收盘批量补缺 | `ssjy_more` 的 PB 与原始 PE 证据；不从成交量字段推算市值 |
| 东财 | 收盘快照最后兜底 | PB、市值；必须有 `f124` 时间戳；动态 PE 不充当 PE-TTM |

字段冲突优先级为 zzshare → Tushare → BaoStock → 腾讯 → 麦蕊 → 魔码 → 东财。
实际请求先尝试便宜的批量历史接口和收盘快照，再执行耗时的 BaoStock 逐股补缺；
到达顺序不改变字段优先级。数据已齐时不额外调用低优先级源。未配 Token、权限不足、
空集、源失败不会阻断其它来源；日志保留安全的状态/错误类型，不记录 URL 或凭证。

市值统一为 **亿元**：zzshare 原值、Tushare 万元除以 10000、腾讯亿元原值、
东财原值元除以 1 亿。腾讯字段 44 是流通市值，45 是总市值。
只有定义明确的滚动 PE 才进入 `pe_ttm`；无法确认定义的报价 PE 保存在 `supplemental`。
BaoStock 净现金流口径 `pcfNcfTTM` 也只留作补充，不覆盖经营现金流口径的 PCF。

口径依据：[zzshare 官方字段文档](https://github.com/zzquant/zzshare/blob/main/FUNDAMENTALS.md)、
[Tushare daily_basic](https://tushare.pro/document/2?doc_id=32)、
[麦蕊接口说明](https://www.mairui.club/hsdata)、
[魔码接口说明](https://momaapi.com/docs-shares.html)，以及 BaoStock 官方 SDK 估值示例。

## 补跑、安全和可重放

- 18:05 首轮、20:05 补跑：每轮估值默认 480 秒预算；08:35 和选股前补跑默认 120 秒。
  预算检查在发起下一次调用前执行，正在执行的一次调用受自身超时约束，不能宣称精确秒级硬截止。
  三个独立同步任务的外层硬超时分别为 1200/900/600 秒，给其它数据与入库留出收尾时间。
- BaoStock 每轮最多 4500 只、仍共用全主机串行锁、登录计数与默认 45000 次/日安全预算；
  配额耗尽、忙碌或冷却即停，不开并发连接，也不绕过已有计数。单次估值 SDK I/O 有 15 秒截止及 EOF 保护。
- 麦蕊、魔码每轮各最多 30 批，每批 20 只，并继续遵守共享日配额和冷却状态；
  整个收盘报价阶段最多使用估值预算的 35%，为历史估值留出时间。
- 实时接口只在目标日期就是当天且已收盘时调用；不把今天查询的实时 PB 填进昨天。
- 部分数据会保存。每 1000 条 BaoStock 有效响应、该轮结束及每个批量源结束后发布同日合并快照，
  下次优先补没有 PE/PB 的股票。跨进程写锁防止两个补跑互相覆盖。
  不按每只股票发布全市场不可变版本，控制数据库写入放大；异常硬杀最多损失本批未发布进度。
- `field_sources` 保存每个字段的来源、有效日期和观测时间。一个检查点对应一个不可变 dataset，
  后续补充不会改变已有 manifest 的历史重放结果；不同日期绝不拼接成一份估值。
- 新复合快照中 PE/PB 均有有限非零值的行才计入可用覆盖；亏损股的负 PE 是有效值。
  只有 PB/市值的行标记 `partial`，保存但不伪装成正式完整估值。
- 日 K 默认覆盖 90%、估值默认覆盖 70% 即可通过数据门槛，并不要求每只股票都有数据。
  未达标时仍保留进度；若上一交易日整份估值满足已有的一日宽限、日历共识与覆盖门槛，
  选股使用那一整份快照并注明真实日期。历史严格策略仍为零宽限。
- 400–500 日初始引导只使用批量历史估值接口，不触发“天数 × 股票数”的逐股请求。

配置参见 `.env.example` 中 `VALUATION_*`。结果包含 `valuation_rows`、
`valuation_stored_rows`、PE/PB/市值分别的 `valuation_field_coverage` 和 `valuation_attempts`，
任务同步记录也保存字段覆盖率与尝试记录。没有市值时，依赖市值的策略仍按缺数据处理，不补零。

## 验证边界

自动化测试使用隔离数据库与模拟接口；不消耗供应商全市场配额。
已在新适配器上单股实测 BaoStock 历史日 PE/PB 和日期通过，登录与查询共消耗 2 次共享额度；
腾讯时间戳与总市值/流通市值方向通过实测。未进行全市场抓取或收盘时段压力测试。
Tushare 路径需要真实账户积分权限才能最终验证，未配置不启用。
本次代码变更不自动触发部署或生产全市场补跑。
