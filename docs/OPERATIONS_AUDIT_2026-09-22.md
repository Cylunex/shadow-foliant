## 本次修复

1. **成交时间闭环**：未带时区的新输入采用上海时区；显式偏移量统一换算。非法日期先拦截，
   按实际时间排序买卖。同一成交的本地时间、`+08:00` 和 `Z` 写法产生相同指纹。存储和查询
   使用新时区标记，Web 不再截取 UTC 小时作为北京时间；历史事实与指纹不批量重写。
2. **收盘计划闭环**：20:20 用本地暖缓存重建持仓与正式候选的次日规则计划。逐股记录日线日期、
   实际生成时间、缓存写入时间、输入行数与哈希；文件时间必须在当日收盘后且不晚于生成时刻，
   不能用当天盘中缓存或四舍五入后的缓存年龄证明收盘数据。120 秒内部预算与 180 秒硬超时，
   无行情、LLM 或通知调用。
   20:45 报告读取时校验交易日和正式运行 ID；新有效计划不会被旧候选附件覆盖。
3. **计划来源可证明**：仅刷新持仓快照不能证明旧计划已重算；生成时间按上海时区判断。
   当日持仓复盘与次日新计划分别读取，防止新止损价抹去当天已有触发。
4. **问财核验边界**：市值同比不能替代市值，排名序号不能替代原值；非有限数、布尔值和超大
   整数不能通过数值核验。股票代码与交易所需匹配 A 股范围，重复股票不能凑足 TOP N，非法
   日历日期不能获得时间核验通过状态。
5. **后验局部失败可见**：外部研究后验异常和 `decision_loop=partial` 会使相应任务摘要降级，
   不再因为外层任务记录为 success 就宣称后验完整。
6. **开发环境说明**：明确当前 Python 3.11/3.12 要求和本地 SDK wheel 安装入口，避免继续在旧
   Python 3.9 环境里把兼容性失败当作代码测试结论。
