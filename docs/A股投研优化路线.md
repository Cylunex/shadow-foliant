# A 股投研优化路线

## 当前取舍

附件建议的方向基本正确，但不应把“换数据源”和“重写系统”混成一次变更。当前优先级如下。

本地 PIT 数据仓、接口限制和 60/120/250 日选股主链的当前实现与运行约束见
[A股本地选股与数据接口](./A股本地选股与数据接口.md)。问财现为并行参考源，不再
参与正式评分。

### P0：先保证结果可信、部署可复现

- 分钟行情采用 zzshare 主源、兼容生产 Python 3.11 的 eltdx 独立兜底，并在 Python 3.12+ 保留 tdx-python 增强兜底；DataHub 统一缓存、路由和质量标记。
- 修正回测印花税的历史分段，并补充涨跌停、停牌、T+1、最小交易单位和无法成交场景。
- 回测成分股必须支持历史截面，禁止用当前成分回放历史结果而不标注幸存者偏差。
- 修复 Docker/Compose 与当前 FastAPI 架构不一致、数据卷遮蔽应用代码的问题。
- 建立可重复依赖锁定；运行时不再依靠全局 `sys.path` 注入和全局 Decimal 转 float。

### P1：让数据质量和业务能力成为显式契约

- 在不破坏现有 DataFrame/dict 调用方的前提下，逐步增加 `source/as_of/fetched_at/stale/quality` 元数据。
- Web、MCP、Jobs 通过应用服务/能力注册表复用用例，不各自拼装底层模块。
- 持仓从不可变成交账本推导；修正通过新增反向记录完成，不原地改历史。
- 引入 ResearchThesis，统一论点、证据、反证、催化剂、风险和失效条件。

### P2：扩展研究能力

- 事件研究与信号命中拆成明确指标，避免用单一“命中率”掩盖样本窗口和基准差异。
- 引入 Qlib/RQAlpha 等组件前先明确职责，只复用其擅长的研究或回测能力，不替换 Foliant 的业务层。
- Media 只在有报告附件用例时接入，不为了架构完整性制造上传页面。

## 不采用的做法

- 不把 easy-tdx 自带的策略、回测或 Web 服务整体引入；其旧协议行情只保留兼容末级。
- 不再新增独立 REST TDX 守护进程；当前进程内 SDK 少一层部署与鉴权边界。
- 不把 akshare/efinance 等聚合爬取库放到分钟行情主链，只保留现有末位兜底职责。
- 不把“登录完成”等同于“多租户完成”；持仓、成交与任务在完成用户级隔离前仍是管理员资源。

## 验收指标

- 行情：主备源字段同构，沪/深/北市场映射、分钟时间语义和成交量单位有自动测试。
- 稳定性：主源异常可在单源超时内降级，旧缓存明确标记，分钟旧数据不能进入实时决策。
- 安全：任何日志、异常和前端响应均不含 Token、请求头、响应正文或个人金融数据。
- 回测：成本、交易规则、成分股时点和指标定义可追溯，默认参数与历史制度变更一致。
