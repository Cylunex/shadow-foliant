# 真实数据验收后的运行加固

## 冻结历史不等于补造历史证据

旧行情表有较长历史，不代表旧选股 Manifest 已保存这些输入。新工具只将当前仓库中
尚未冻结的前复权行情保存为不可变观察，供**此后新生成的选股**引用。旧 Manifest、
原行情价格和原抓取时间都不变；新增载荷明确标注实际冻结时间及
`legacy_capture_not_historical_pit`，不能作为过去就已知道这些数据的证明。

先运行标准迁移（包括 `13-market-history-freeze.sql`），备份后再操作：

```bash
# 默认只审计，不写数据、不请求任何数据源。
python scripts/freeze_market_history.py --through YYYY-MM-DD

# 显式执行；每批最多 10,000 行，每次最多 20 批，默认 5,000 行 / 1 批。
python scripts/freeze_market_history.py --through YYYY-MM-DD --apply --batch-size 5000 --max-batches 1
```

日期必须替换为实际截止日。每批独立事务，失败回滚；重复执行只处理仍缺观察的行。
工具使用独立发布代次，使跨越冻结操作的并发选股放弃发布，不倒退日行情的新鲜度。
不要在正式选股执行窗口操作，也不要把 `frozen_rows=0` 当作全量完成：并发锁定行可能
被跳过，最终应以 `after.unfrozen_rows=0` 为准。

`replay_selection()` 新增 `reason` 和 `frozen_market`：冻结行数、股票数、最长历史、
所需历史和历史达标股票数。`live_history_fallback=false` 始终表示不会偷用当前表来
“修好”旧重放。历史不足仍诚实返回不完整，不绕开硬门槛。

## 正式选股与盘后采集各有就绪口径

- `/selection-readyz` 默认始终使用当天盘前上下文，并要求正式选股日期匹配。
- `/data-readyz` 默认到 18:05 才切换盘后口径，对应日 K、复权因子发布后的同步窗口。
- 16:00–18:05 增加 `postclose_acquisition.status=pending_scheduled_sync`；此时顶层
  `ready` 仍表示既有决策输入是否可用，不声称当日盘后数据已到齐。
- 晚间同步刷新盘前和盘后两份代次缓存。代次变化、缓存缺失/过期仍保持失败关闭；
  健康探针本身不触发全市场扫描。18:05 是同步开始时间，不保证该时刻立刻 ready。

## 问财降级

HTTP 401 冷却 1 小时，403 冷却 15 分钟，429 至少 120 秒（支持秒数形式的
`Retry-After`，上限 1 小时），5xx 冷却 60 秒。拒绝原因可从异常 HTTP 状态和
`rejection_status()` 聚合字段诊断，不输出 Cookie 或响应正文。

同一进程只允许一个未完成请求；外层超时不代表后台线程已结束，后续请求直接降级，
不扩大线程池或堆队列。进程间限流继续由共享 provider governor 执行。
此优化减少无效重试，**不能修复上游鉴权/反爬**；问财仍只作独立参考，不阻断本地排名。

## 封存评测

构造 evaluator 时先检查文件权限、摘要格式和 Docker，再以公开合成输入运行既有
摘要固定、无网络、无挂载 worker。此步骤不打开封存文件、不消耗批次。失败即停止；
只有预检通过后才进入原来的原子预留及读取流程。正式评测期间仍可能发生新故障，
已预留批次继续遵守失败留痕/退役规则，不自动重开或重复消费。

本轮没有安装 Docker，也没有消费真实封存批次。

验证重复执行不重复写、冻结输入可读回、全部原行情字段不变、数据源请求数为零。
