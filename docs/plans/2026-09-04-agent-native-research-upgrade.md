本文保留改造前审计和设计目标，不将下方历史缺口描述冒充当前代码。
实际实现、数据缺口、可选扩展和验收边界见 [研究决策闭环使用说明](../RESEARCH_DECISION_LOOP.md)，
逐项状态见 [实施清单](../../openspec/changes/research-decision-loop-v3/tasks.md)。

代码核对基线：本地 `main`，`e6c3e1f90cbc90f3b44f421da5aacac324956d36`。本轮没有拉取覆盖工作区、连接生产数据库或重新检查线上日志；不把本地审计结论当作 9 月 4 日生产故障报告。外部资料于本日查询，以原项目、官方文档和论文为依据；没有复现其收益宣称。

## 1. 结论与产品方向

建议把目标从“每天多找几只股票”升级为：

> 找到值得研究的机会 → 判断是否适合当前账户 → 留下可执行建议 → 跟踪执行与未执行结果 → 用可靠证据改进策略。

保留 A 股、Agent 优先、人工决定交易的定位；不被现有 `8+5+2` 配额、固定指标集合或模块划分永久束缚。允许以后引入因子生成、学习排序、市场状态适配与持仓替换研究，但必须把研究自由与正式发布权限分开。

优先解决四件事：

1. **策略到底有没有增益**：净收益、可成交性、样本独立性、失败实验全部可查。
2. **今天到底需不需要动账户**：选股名单不等于买入清单；加仓、减仓、换仓和不动都可以是结果。
3. **收益为什么与感觉/账单不同**：报价、成交、资金变动、费用和公司行为统一对账。
4. **Agent 能不能少查代码、多完成事情**：稳定的用例工具、可引用上下文、增量解释与权限明确的操作预览。

不要求改造完先整体影子运行几周。每个通过验收的功能可直接启用；“前向验证账本”是长期评估设施，不是阻止上线的等待期。**尚未证明有效的新策略不能因为基础设施上线就被自动判为有效。**

### 继续尊重的用户偏好

- 默认偏好：主力资金、低价擒牛、低估值 > 小市值 > 净利增长。作为可见、版本化的偏好先验，而不是宣称前三类已经有更高真实收益。
- PIT 每行业最多 5 只继续保留；行业数量约束与组合资金暴露约束是两回事。
- TOP15 与独立 TOP5 推送保留；不为了“看起来不同”强行更换 TOP5。
- 问财、妙想的原始选股名单继续作为外部参考，不做重复命中投票。
- 盘前、盘中通知不擅自缩减；仅盘后默认精简。颜色遵循 A 股红涨绿跌，并辅以涨跌文字。
- RAG 不恢复，旧表清理不属于本方案执行范围。
- 夜间任务尽量 23:30 前结束，24:00 硬截止；周末高 token 任务避开 09:00–12:00、14:00–18:00。

## 2. 对附件方案的修订

| 附件方向 | 本方案处理 | 原因 |
|---|---|---|
| 先做三栏工作台 | 改为先做小型上下文契约，复杂 UI 后置 | 用户主要经 Agent 使用；证据和行动闭环更有价值 |
| ResearchThesis、Capsule 从零新建 | 扩展现有 `application/research_artifacts.py` | 已有 thesis、evidence、invalidation、provenance，不再建立第二套工件体系 |
| 正式数据必须单一 provider，主源失败就停 | 改为冻结**合成数据的来源与版本** | 当前多源补齐有必要；应禁止冻结后静默变更，不是禁止冻结前有规则地切源/合并 |
| 每日前向影子账户 | 改名“前向验证账本”，与生产同期启用 | 防止与用户不需要影子部署、现有交易行为诊断模块混淆 |
| 一份最终盲测集永久只看一次 | 按研究批次管理封存集，使用后退役 | 永久反复读取同一集会失去盲测意义；新 PIT 历史短也不能虚构长年盲测 |
| LLM 永远只能改几个配额 | 扩展成政策建议、假设生成、受限因子研究三层 | 允许真正拓展能力，但研究代码与正式发布隔离 |
| 因果 ID 与收益因果归因 | 使用“决策谱系与收益分解” | ID 串联只能说明出处，不能证明某策略导致收益；增量价值仍需对照实验 |
| UI、回测、Agent 所有值相等 | 相同输入版本、计算配置及语义下相等 | 实时报价、历史因子、账本成交价本来就不应混为一个值 |

资料准确性也需调整：AlphaEval 初稿是 2025-08，2026-06 修订并注明 KDD 2026，不宜笼统写成首次发表于 2026。其“无需回测”的快速多维评价不能替代 A 股成交与账户验证。[原论文](https://arxiv.org/abs/2508.13174)

## 5. 目标架构：五条闭环，共享一份事实

| 闭环 | 输入 → 输出 | 主责 |
|---|---|---|
| 数据闭环 | 源观测 → 语义校验 → 同日快照 → 质量报告 → 缺口修复 | 稳定、时点正确、有限额 |
| 研究闭环 | 假设 → 因子/策略版本 → 实验 → 对照 → 发布决策 | 找到真实增量，不积累漂亮报告 |
| 选股闭环 | 可投资快照 → 三条本地提名 → TOP15/TOP5 → 冻结工件 | 机会发现、可重放 |
| 账户闭环 | 正式机会 + 持仓现金 + 交易条件 → 行动计划 → 人工成交/模拟成交 → 对账 | 判断是否值得动、能否做到 |
| Agent 闭环 | 受权上下文 → 原子工具/研究 SOP → 引用结论 → 反馈 | 少查代码、少幻觉、少无效调用 |

共同版本键：`run_id / manifest_id / policy_version / feature_version / portfolio_snapshot_id / evidence_revision`。它们追踪来源，不应命名为“已证明因果关系”。

不必全部做成独立服务。第一阶段仍是现有 Web + jobs + PostgreSQL + 缓存；只有任意代码研究 Worker 需要真正独立安全边界。

## 6. 数据层：从“源很多”变成“知道哪个字段能用”

### 6.1 能力、质量和日期分开

扩展现有 `source_contracts`、`runtime_capabilities`、`valuation_contract`，而非新造同义 Registry：

- 能力：历史/实时、行情/估值/财务/公司行为、市场覆盖、授权、配额、可否并发。
- 字段语义：PE-TTM/静态 PE/动态 PE、PB、单位、复权、事件生效时间。
- 数据时间：`effective_at / published_at / first_seen_at / retrieved_at`，另记录修订号。
- 运行健康：超时、空集、权限不足、限流、字段漂移、质量不合格分别统计。
- 可用性：HTTP 成功率不是有效行覆盖率，数据完整也不等于当前决策可消费。

来源优先顺序是**字段级策略**。健康度可以让某源暂时跳过，但不能把定义不同的 PE 互相替换。自适应路由只在规定的候选来源中工作，并记录为何选择它。

### 6.2 冻结前允许补齐，冻结后禁止暗改

1. 在限定日期、字段定义和预算内尝试稳定源，再尝试不稳定源。
2. 同日的不同来源字段可按已定义规则合成；保留每字段出处与冲突证据。
3. 冻结后形成不可变 dataset/manifest。后续补齐发布新 generation，不覆盖历史。
4. 无法取得目标日完整估值时，可沿用已批准的最多一交易日**整份**快照规则；不跨日逐行凑齐。
5. 财务、报价、公告各自有新鲜度策略，不能一律“3 天内算新”。
6. 空结果原因不明就写 `empty_unknown`，不能武断归因为“未发布”。

覆盖率至少同时看全市场、目标行业、候选股票、必需字段。99% 不能直接等价成功，但应按消费需求通过或降级，不能因不重要的 1% 缺口一概停机。

### 6.3 资产就绪与补跑

任务声明 `consumes / produces / partition_date / deadline / request_budget / retry_policy`。上游脚本成功但数据不合格，下游不能开跑；上游部分成功而下游所需字段齐全，则可继续。

建议结果状态：`ready / usable_degraded / waiting_source / blocked_quality / failed_system`，额外保存 `decision_usable` 与 `ingestion_complete`。兼容旧状态由适配器映射，不能一次更改所有 API 返回值。

- 只补缺失分区和字段；保留断点，不重复拉满市场。
- BaoStock 沿用全主机单连接串行、登录计数、共享自然日额度；日预算默认 45000，绝不突破用户给定 50000 上限。研究 Worker 也走同一预算，不各算各的。
- 更新时刻作为发布日历提示，实际 publication/check 才触发依赖；星期、自然日、交易日明确区分。
- 前向账本结算等计算任务不额外调用全市场接口，消费已入库数据。
- `/data-readyz` 从预计算 QualityReport 读取；报告与 generation 绑定，过期显示 stale，不能缓存一个永远为真的 ready。

验收目标：只读就绪接口热态 p95 < 1 秒（待实测校准）；缺口、下一步、预算消耗可被 Agent 一次读到；故障恢复不重复发正式选股通知。

## 7. 从 TOP5 到“适合我的行动计划”

### 7.1 正式机会与账户行动分开

保留三种输出，避免一张表承担所有任务：

1. `OpportunitySet`：TOP15 和研究 TOP5，反映本地策略发现的机会。
2. `ModelPortfolio`：独立模型账户的目标权重与现金，不受用户临时成交影响，用于验证策略。
3. `AccountActionPlan`：结合用户持仓、现金、可卖数量、当前报价、行业/主题暴露后的加减仓/换仓建议。

TOP5 可以与 TOP15 前五相同，只要规则确实得到相同结果；也保留当前从完整合格候选集中独立优选的能力。展示新增、落选及约束原因，不以 Jaccard 越低越好为目标。

### 7.2 增量价值，而不是见好股就买

行动规划的比较对象至少包括：保持不动、只减风险、增持已有、买入新标的、等额替换。所有方案都需考虑成本与风险预算。

候选研究优先级可综合“净增益估计、置信区间、组合相关性、换手成本、流动性和研究失效条件”。这些项不能生拼成未经验证的神奇分数；先用规则/等权基线，再测试更复杂优化器。

- 高仓位时优先给出“不动/替换/减重叠暴露”，不机械新增持仓。
- 市场允许加仓，不代表个股有合格买点。没有合格对象时输出“允许加仓，但今天没有满足条件的标的，暂不操作”。
- 行动计划引用原正式 run，不修改原排名。盘中报价过期、现金水位变化或用户新增成交时，原计划失效并重算。
- 新增 `holding_version`、`quote_as_of`、`expires_at`、`invalidation_conditions`、`blocked_reasons`。
- 投资偏好、风控约束、市场状态与研究信号分层裁决；LLM 解释裁决，不凭文字覆盖硬约束。

### 7.3 组合解算

先按交易日对齐收益矩阵，避免停牌和缺数据导致错配；估计窗口、缺失处理、协方差收缩及成本规则写入模型版本。

约束包括：单票、行业/主题、总仓位、现金下限、可卖数量、最小交易单位、换手预算、流动性与不允许交易名单。ETF 单独处理资产类型与跟踪暴露，不能一概套股票的基本面门槛或交易规则；没有持仓穿透数据时明确 unknown。

求解失败时给出冲突集合，返回持有/确定性保守方案；不能偷偷剔除股票后把所有权重归一到 100%。解算结果需再次经过交易单位离散化、现金校验与硬风控。

## 8. 前向验证账本与收益对账

### 8.1 三本账不能混

| 账本 | 回答的问题 | 允许的解释 |
|---|---|---|
| 信号后验 | 被选中后价格如何变化 | 研究诊断，不含真实可成交性 |
| 模型前向账本 | 按当时公开可执行规则操作会怎样 | 计费用、未成交、现金和公司行为的模拟结果 |
| 用户真实账本 | 用户实际交易和资产变化怎样 | 来自成交/资金/持仓事实，不反推伪造成交 |

在同一图表展示但分开标识。不能用模型收益给用户真实账户报喜，也不能因用户没买而认定选股失效。

### 8.2 严格的可交易时点

当前提名记录把 `selection_date` 写入 `data_as_of`，后验取它之后下一交易日开盘，这是保守的次日口径，不是已经发现了“09:45 却按当天 09:30 买入”的事实。新增账本要拆开这些易混字段：

`market_as_of ≤ decision_at ≤ published_at < earliest_execution_at`（不同字段按真实时间粒度记录）。

- 现有 09:45 结果默认从次一交易日开盘模拟；若研究同日执行，则需 09:45 发布后的下一可交易 bar 和可靠分钟数据。
- 仅有日线时，不能假设当天开盘、最低价或完美买点成交。
- 1 日标签可作为价格观察，但对 T+1 股票不能解释为买入当天收盘平仓净收益；实际交易账本按可卖时间处理。
- open 缺失不静默替换 close；标记缺数据/未成交，或按事先声明的另一执行模型记录。
- 涨跌停、停牌、流动性不足、手续费、税费、公司行为按品种和生效日期处理；具体市场规则实施前核对官方资料，不能把单一“100 股/T+1”规则套所有 A 股相关品种。
- 原始价格做现金/数量账；复权序列用于研究。分红若已体现在总回报序列，不得再重复加现金收益。

### 8.3 对照与统计

固定比较：PIT-only、当前融合、去掉某条赛道、等权/低换手基线、适配风格的市场基准。输入日历、资本、执行时点、费用、持有规则全部一致。

两类评估分开：每期候选固定持有 1/3/5/10/20 日的 cohort；持续滚动的可交易账户。不能把重叠 cohort 收益累加成单账户收益。

真正最大回撤按净值峰值到谷值计算；MAE 单列。未成交机会损失只作反事实诊断，不能当实际损益。多策略同时提名保留贡献关系，使用 leave-one-out 等对照评估边际价值，不重复认领整笔收益。

### 8.4 收益统一账单

扩展现有成交/现金流与每日快照实现，不另造财务系统。基础恒等式：

`期末权益 - 期初权益 - 外部净流入 = 本期投资损益`。

内部买卖资金不是外部入金。投资损益进一步分为价格变化、已实现损益、分红、费用等，并确保分解互不重复；TWR、资金加权收益和金额损益分别标记。缺少精确资金流时点时说明采用日内约定或近似，不伪装成精确 TWR。

先明确 `account_scope=securities_only/full_account`：当前证券市值子账可以把买卖看作该子账的进出流，这不等于完整账户的外部出入金，不能直接套用上式而不改边界。现金、出入金或费用记录不全时只展示可核验的证券侧结果，不推测账户总收益或可用资金；现金未知的行动计划不给伪精确买入金额。

金额账逐步采用 Decimal/最小货币单位与明确舍入，研究矩阵继续浮点；当前 `_bootstrap.py` 仍有全局 NUMERIC 转 float 兼容逻辑，新账本应局部绕开并测试，不能一次全局移除导致旧模块出错。

引入带版本的 ReconciliationReport：同一快照下 Web、Agent、通知金额应一致；证券数量、现金或行情时间不一致时显示差异来源。沿用用户既有“后补成交不追究当日收益”的口径，记录调整/重述版本而不是偷偷改原通知。

## 9. 真正有用的策略自进化

### 9.1 三层自动化，不再只有“每周问一次 LLM”

| 层级 | 允许能力 | 发布边界 |
|---|---|---|
| 日常自动诊断 | 数据异常、漂移、信号衰减、成本与未成交变化；产生实验建议 | 不按一天盈亏频繁改参数；安全性收紧按预设确定性规则执行 |
| 周度政策控制 | 在已批准范围内调整优先级、配额、阈值、持有/换手政策 | 结构化提案、成熟证据、整体步长、回放验证、未来生效、可回滚 |
| 隔离研究实验室 | 生成因子 AST、规则组合、学习排序、事件假设，记录失败并迭代 | 只能写试验区；代码/新模型成为正式版本前另走测试与发布，不由 LLM 直接改生产 |

初期 `8+5+2` 是保守基线，不是永久目标。证据足够时可以提出新的配额策略，甚至比较成本感知的学习排序；扩大允许修改范围必须作为一次明确政策升级，而不是通过提示词偷偷扩权。

### 9.2 第一批控制器修正

- 严格结构化 schema，拒绝多余字段、重复 path、bool 数字、非有限数、非整数配额；模型不支持结构化输出时只能严格解析一个对象，失败即保持旧政策。
- 所有步长相对提案开始时基准计算，再约束总变化量；拒绝在一个提案内用多个小步骤绕过。
- 约束按风险方向定义：例如降低入选阈值可能增加风险，不能简单把“数值减少”当安全降级。
- 提高五策略权重同样需要证据，不只给基因组/卫星数量设样本门。
- 样本门使用独立日期、去重股票、重叠持有期处理后的有效样本，以及置信区间；20/30 条提名不是可靠性保证。
- 按策略版本/数据制度/执行模型分组，避免旧版好成绩替新版背书。
- 原始响应如有审计需求，只进入限权工件存储并脱敏/设留存期，不进入普通日志，也不保存不必要的敏感推理文本。
- 数据库原子 CAS 校验 `base_policy_hash`，校验、发布不能存在竞争窗口；同一 proposal 幂等。
- 使用明确的下一个交易决策生效时间，不依赖“下一自然日”；保留冷静期与一键回退到已验证版本。

### 9.3 实验谱系与评估门

在现有策略变体、研究 Run 之上增加 `hypothesis / trial / factor_version / lineage_edge / evaluation / promotion`，优先复用表与工件，避免同时引入 MLflow、Qlib Recorder 和第二套私有 Trial Registry。

每次试验在开始前登记：假设、父版本、搜索空间、数据 manifest、种子、代码/环境锁、目标、预算、标签区间、基准和停止条件；失败、超时、被否决也保留。

评估顺序：

1. 数据/PIT/单位/未来信息检查；固定样本或不完整历史行业暴露不能冒充全市场严格 PIT 证据。
2. 快速预测、稳定性、扰动、冗余和经济解释筛选；不是再次增加一批同义指标。
3. 滚动训练/验证；按标签实际区间 purge，必要时 embargo，预处理只能在训练段拟合。
4. 成本与可成交净收益对照；调整多重试验偏差，报告区间和有效样本，而非只看最高 Sharpe。
5. 候选冻结后由独立评估权限读取批次封存集；一旦结果用于调整，此集退役为验证资料，后续换新的封存区间。
6. 发布后继续前向观察；达到预先定义的漂移/损失/数据失效条件时收紧或回退。

已有市场历史不等于多年严格 PIT 财务历史。分别保存 `strict_observed_pit`、`reconstructed_history`、`exploratory` 标签；数据不够时可以继续研究、继续用当前已验证策略，但不能用降级样本自动晋级新模型。

### 9.4 值得新增的研究方向

这些是待检验假设，不是已经有效的买卖指标：

- 盈利质量：经营现金流与利润偏离、应计项目、营运资本压力；先审计与现有财务质量指标的重复。
- 资金持续性：3/5/10 日一致性、价格冲击与资金流背离；不同供应商的“主力”定义先统一，不能混成同一时间序列。
- 趋势衰减：沿用用户“10 日中 7 涨、累计 15%”作为过热候选状态，再研究回撤、量能、市场广度确认，不触发一个条件就机械卖出。
- 行业相对强弱与拥挤：个股相对行业、行业相对市场；历史行业归属不足时标探索。
- 事件窗：业绩修订、回购实施、减持、解禁等有明确时间与正文证据的事实；标题热度不能直接晋级。
- 市场状态：趋势、波动、广度、流动性驱动的简洁状态机，带滞回/最短保持期；先于复杂隐状态模型或强化学习。
- 学习排序：用现有因子和候选元数据比较简单正则化模型/树模型；不把任意 lane_score 当可直接相加的统一尺度。

每个方向先登记一个小实验、一个朴素对照和明确淘汰条件；先做 2–3 个，不同时把七条都放进正式评分。

## 10. Agent 与 Web：围绕用例，而不是围绕内部函数

### 10.1 上下文工件升级

沿用 `research-artifact-v1`，新增版本化扩展或 v2；不要仅为新名字复制一套 `research_context` 服务。

冻结部分：正式 run/manifest、证券身份、时点、因子分项、约束入选/落选原因、数据质量、研究论点与证据版本。动态 envelope：最新报价、当前持仓版本、有效期、阅读权限。

同一冻结工件重复读取内容哈希不变；freshness 可以随时钟变化，但不改历史事实哈希。主题/策略的参考关系与正式贡献分开。对“为何排名下降”分别给出数据变化、政策变化和约束变化；非线性约束交互不可强行拆成精确因果贡献。

先新增/整合 5 个用例（最终名称以现有契约命名规范为准）：

- `research.context.read`：给 symbol/run，得到有限长度摘要和引用 ID。
- `research.context.compare`：比较两次正式运行或冻结策略版本。
- `portfolio.action.preview`：仅个人投资授权可用；给出行动草案及阻断原因，不下单。
- `strategy.evidence.read`：净收益、有效样本、失败实验、当前版本差异。
- `operations.research-health.read`：脱敏业务健康摘要，不暴露服务器或配置秘密。

工具描述提供字段意义、示例、默认值、日期语义、缺参补全边界与错误码。证券名/代码解析复用成交导入解析，不让 Agent 每次查内部代码。歧义证券必须确认，禁止按名称猜代码提交。

复用现有 application/Run/Outbox/Nexus Review；普通研究 Profile 的上下文不附带用户持仓，个人上下文独立权限与缓存键，不能经引用 ID 侧漏。

### 10.2 工作台与通知

不内嵌第二套 DSH/Agent Runtime。前期在现有页面加“解释本次结果 / 与上次比较 / 发送受权上下文 / 查看证据”；有稳定 API 后再升级三栏布局。

首页优先显示：今日动作、现金/风险空间、TOP15/TOP5、新增/退出理由、数据降级、策略版本变化、模型与真实账户收益差异。K 线与指标服务研究，不做多市场交易终端。

盘后通知采用“今天发生什么、现在要注意什么、下一步是什么”，详情通过链接展开。盘前/盘中保留现有信息密度，仅修正矛盾、时点和动作一致性。提示“无需操作”是正常产物，不通过增加提醒条数体现系统价值。

### 10.3 Agent 质量与成本

把现有 `agent/evals/plugin-contract-cases.yaml` 的说明性用例升级为可执行夹具；已有测试继续保留。

覆盖：未来公告、同名证券、复权混用、元/万元/亿元、空数据、冲突来源、提示词注入、污染工具返回、过期会话、无权限工件、失败重试、重复成交导入。

指标包括：无证据结论率、证据引用覆盖、时点错误、工具调用成功率、越权次数、每个任务 token/耗时、无效重试率。对固定数据版本的重复回答记录决策稳定性；对真实变化不盲目追求低翻转率。

LLM 调用采用先确定性筛选、再批量摘要、最后按需深研；以工件哈希/模型/提示词版本缓存，证据变化才失效。每日诊断默认不需要 LLM；周度只处理成熟样本与显著变化，月度再做研究方向复盘。

## 11. 工程治理与分期交付

### 11.1 模块收敛，不做一次性大重写

- `application` 成为 Web/MCP/jobs 共享用例入口；传输层只负责认证、schema、序列化。
- 从现有实现逐步抽取共享量化函数：指标、因子、成本、可交易性、评分和约束；按已证明重复的函数迁移，不建立空壳“大内核”。
- 锁定运行依赖和可选研究依赖，保存环境哈希；研究库不拖大常驻服务镜像/venv。
- 将健康状态、任务阶段、资产 generation、配额预算做结构化记录；通知日志只记录安全元数据。
- 文档增加“当前有效/提案/历史”标签和唯一入口；本方案不修改现有架构文档以假装已经上线。
- 不为源码重构增加数据库重建、RAG、Kafka、Kubernetes、向量库或图数据库依赖。

### 11.2 推荐实施包

下列是增量交付顺序，不是未经评估的工期承诺。首批验收后可直接使用，后续继续积累证据。

| 包 | 内容 | 依赖 | 完成标志 |
|---|---|---|---|
| A：可信基础 | 控制器校验缺口；时间/指标语义；收益日期对齐；质量报告缓存；工件最小上下文 | 无 | 非法提案全部拒绝；既有正式结果 golden replay 不变；查询不触发重评分 |
| B：评价与对账 | 区分信号后验/模拟账户/真实账户；统一成本和未成交；基准与版本化对账 | A | 可从冻结决策重放到账户净值；不能虚构成交；三个入口数字一致 |
| C：账户行动 | 持仓感知、不动/替换对照、约束解算、有效期和版本水位、简洁结果 | A，B 提供评价基础 | 高仓位有明确“不动/替换”结果；无买点不输出强制买入；不改正式排名 |
| D：政策自进化 | Trial Registry、独立样本、滚动验证、跨实验校正、原子发布/回滚 | B | 增加暴露必须通过证据门；旧/新版本持续独立跟踪 |
| E：研究拓展 | 因子谱系、2–3 类新假设、可选 Qlib/RD-Agent/排序模型研究 Worker | D | 沙箱不可访问生产/封存集；只产试验；能复现失败与收益 |
| F：体验强化 | 工作台、上下文比较、事件证据时间线、可执行 Agent 评测 | A 起步，B/C/D 按需接入 | Agent 常见任务不用查代码；Web 与 Agent 读取同一工件 |

A 的小型上下文工具与后续包并行演进，不必等全部账本功能完成才改善 Agent 使用。相反，大型图表和三栏界面不阻塞 A–D。

### 11.3 验收与迁移规则

1. 单元/合同测试、冻结数据重放、小样本真实源字段验证分别执行；自动测试不消耗全市场配额。
2. 补充跨入口数值一致性、截断未来数据一致性、指标预热差异、重复提交、乱序/修订事件场景。
3. Schema 只做兼容扩展；旧记录保留原指标版本，历史价格标签不升级冒充账户净收益。
4. 对历史回算标记 `backfilled`，没有 contemporaneous 记录的结果不冒充当时已发布的前向决策。
5. 新 Run 绑定新的语义与代码版本，旧 manifest 继续原样重放；计划工具默认不触发正式发布。
6. 每包独立上线/回滚，重大策略行为变化单独列示；部署和券商执行仍需明确授权。
7. 性能目标、统计阈值与预算先作为配置候选，用实际样本校准；不能用本方案建议的数字充当策略有效性证据。

## 12. 本阶段不做，但保留的扩展口

- 不新增自动实盘下单、MiniQMT 网关、多市场交易；若以后需要，单独设计授权、风控、模拟验收与紧急停止。
- 不恢复 RAG。实验负结果、引用关系、事件修订先用结构化表和全文检索；只有检索评测证明不足才考虑其他技术。
- 不一口气接入所有外部研究框架；先建立统一输入/输出，让算法可替换而业务不依赖某库。
- 不把每篇新闻变成因子。允许将**验证过的结构化事件特征**升级为本地正式因子，但须独立假设、PIT 和对照评估；问财/妙想名单仍不投票。
- 不把“全自动进化”理解为每周必须变化。维持、拒绝、降低暴露都是有价值的进化决策。

最终交付应让用户直接问清楚：**为什么选它、现在适不适合买、如果不动会怎样、策略是否真有额外收益、收益差异出在哪里、这周究竟改了什么。**

配套 OpenSpec 草案见 [research-decision-loop-v3](../../openspec/changes/research-decision-loop-v3/proposal.md)。
