## 当前缺口

`application/research_cases.py` 的 `compile_claim` 已支持 Decimal 重算及四项口径一致性，
但重算通过就写入 `state=supported`；`validity` 随后可能把整个文字论点投影为 supported。
即便文字是因果推断，`semantic_entailment=not_automatically_proven` 也没有约束这个聚合结果。
发布时间与首次观测时间只校验格式，没有与草稿生成时点比较。数字子串匹配也可能把
`1,200` 中的 `200` 当成完整数值。

## 实施方案

1. **一个核验实现**：抽出纯函数模块，保留原 `compile_claim` / `validity` 导入入口。
   数字、来源字段、时点、声明口径、文字支持程度分别输出，不用一个“可信分”代替。
2. **冻结证据截止时点**：草稿由服务端记录时点，不接收 Agent 自报的核验结果或截止时点。
   要求发布时间 ≤ 首次观测 ≤ 截止时点。锁定沿用草稿时点，不能用后来材料美化旧论点。
3. **完整数字核对**：支持普通小数、负号和千分位；拒绝子串、非有限数和不受支持的数字表达。
   保留原单位、币种、口径、期间类别检查；不擅自换算币种，不推断实体、财报期间或来源真实性。
4. **历史兼容与可见结果**：不迁移或覆盖旧记录；读取时按当前规则重新评估，并返回逐条原因。
   草稿、锁定论点、私人 MCP 和浏览器读同一结果；缺少旧时点的记录明确未知。
   页面展示“数字已重算 / 文字待核实”、过期状态和引用定位，不新增人工审批步骤。
5. **工作流回归**：使用本地合成证据验证保存、重复锁定、旧版本不可变、owner 隔离、HTTP 错误
   与未来材料拒绝；覆盖时区、千分位、负数、零分母、伪造 supported 和历史坏记录。

## 完成标准与边界

- 算式正确的因果结论仍未核实；人工锁定也不会把证据自动变成已认证。
- 正常的已过期资料可以保留草稿，但显示需复查；未来引用不能提交为当时已知证据。
- 原 API 参数兼容，新增检查结果为加法字段；旧 `supported` 会按真实核验能力降为未核实。
- 无新增运行依赖、数据库迁移、外部调用或真实通知；不修改正式候选与账户。
- 本地测试、上线状态和自然效果分别记录；论文成绩不作为本项目验收结果。

后续可单独评估有权威来源回执的主体/财报期间绑定、真正的文字蕴含评测、私有封存案例与
概率判断校准；这些需要额外事实或明确评估预算，不在本次实现中作已完成承诺。
