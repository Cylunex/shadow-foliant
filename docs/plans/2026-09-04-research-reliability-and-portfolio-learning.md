# 下一阶段方案：可核验研究、持仓复查与有边界的策略学习

日期：2026-09-04。状态：**已进入 0.6.0 实现，外部环境验收未完成**。

本文保留原始设计与验收目标；实际代码范围、限制和验收结果以
[0.6.0 实现说明](../RESEARCH_RELIABILITY.md) 为准，不把设计目标视作全部实测通过。

代码基线：本地 `b3eec20` / 0.5.0；不把本地代码状态当成 NAS 部署状态。本轮未连接生产、未重新运行业务测试、未调用收费行情或模型接口。

前置设计：[上一阶段方案](2026-09-04-agent-native-research-upgrade.md)。已交付范围与外部验收缺口以 [0.5.0 说明](../RESEARCH_DECISION_LOOP.md) 为准。本方案整合三份用户材料，纠正其中的基线假设，增加近期公开研究与工程参考，不将它们的收益或准确率直接外推到 A 股。

## 1. 总体判断

下一步不应推翻正式选股，也不应只做“研究日记”。建议把现有系统接成一条能回答具体问题的链：

```text
合格、可追溯的输入 → 本地三赛道正式 TOP15 / 独立 TOP5
                              │
                   入选原因 + 必须核查的问题
                              ↓
                    个股档案 / 论点 / 反证
                              ↓
                  账户行动预览 / 用户实际操作
                              ↓
             净收益对照 + 判断校准 + 原因分类
                              ↓
                  有预算、有证据的策略调整

问财 / 妙想 / 新闻 → 参考、发现、研究证据；不直接改变正式排名
```

本轮最重要的排序是：**先补齐能用的证据，再讨论更聪明的进化；同时尽早交付持仓复查，而不是等一整套研究平台建完。**

继续保留用户已经决定的边界：

- 本地 PIT、本地五策略、技术基因组都是真实候选来源；问财、妙想是外部参考。
- 主力资金、低价擒牛、低估值优先于小市值，净利增长权重最低；保留目前已确认的赛道设置。
- PIT 每行业最多 5 只。它不等于账户行业资金暴露上限，也不是要求 TOP5 配满同一行业。
- TOP15 与独立 TOP5 推送继续保留；新增研究不替换正式名单。
- 不恢复 RAG，不新增券商下单，不全市场逐股生成长研报。
- 工程功能验证后可以直接使用，不强制全系统等待长期影子运行。新的增风险策略仍须过证据门；已有策略不因新账本样本尚少而全部停用。
- 不缩减盘前、盘中通知；新增摘要复用盘后/周报入口。A 股红涨绿跌，风险状态另配文字与图标。

## 3. 对三份材料的取舍

| 材料主张 | 处理 | 修订原因 |
|---|---|---|
| Dossier、ThesisLock、预测账本已是基线 | 纠正 | 当前只有研究摘要，长期对象和裁决链仍需建设 |
| 关掉周度政策进化，全面转研究台 | 不采纳 | 与用户保留本地选股和策略自进化的目标不符；改为证据驱动、只调授权白名单 |
| 新版本必须统一 shadow → active | 改写 | 工程增强直接启用；未验证 alpha 的观察不阻挡现有服务，也不作为额外全系统等待阶段 |
| SourceAccess、Claim Compiler、Validity | 采纳、收敛 | 统一成证据服务，不建多个平行真相库；声明观测覆盖范围 |
| ResearchEpisode、DecisionEpisode、DecisionRound 三套账 | 合并 | 一份 ResearchCase 组织长期问题，既有 Run 执行，决策清单绑定发布与账户预览 |
| 没有 Thesis 不允许任何 Action | 不采纳 | 硬风控退出、用户自主操作和历史成交导入不能被阻挡；只限制“已完成研究审核”的宣称 |
| 新事件不能映射预登记变量就只能 WATCH_ONLY | 放宽 | 新的重大风险可能恰恰不在旧假设中；应触发紧急复核，确定性硬风控照常生效 |
| 同一快照全部 artifact 必须字节一致 | 精确化 | 确定性决策内容规范化哈希一致；运行 ID、时间、遥测、LLM 措辞可以不同 |
| 换模型/工具路径变化就算失败 | 精确化 | 检查必要证据、数字和权限不变量；合理不同路径可以通过，路径差异只作诊断 |
| 哈希链/签名证明不能被篡改 | 降低承诺 | 哈希验证内容一致；有可信锚的签名可提示篡改，不证明事实正确，也不抵抗同机最高权限重写所有记录 |
| 用共同假设图做自动仓位决策 | 分阶段 | 先人工确认标签、展示集中暴露，不能让 LLM 猜出的产业关系变成硬仓位参数 |
| 动态不确定度、Kelly、重型因子工厂 | 延后 | 数据与检验不足时，复杂公式不会增加可信度；先做可解释的策略健康与压力情景 |

资料核验注意事项：FrontierFinance 评分器 README 称数据无需登录，但 [数据集页面](https://huggingface.co/datasets/samaya-ai/FrontierFinance/tree/main) 当前显示 gated 条件，不能安排无人值守直接下载。FinSkillBench 的编号月份、搜索标注与摘要页提交日期存在差异，本方案只标 2026 年，不拿“8 月最新发布”作论据。未逐一核实的附件星数、产品发布日期、模型榜单和其余论文收益数字不进入验收依据。

## 5. P0-A：把“取到数据”升级成“知道数据能用在哪里”

### 5.1 扩展现有合同，不另建数据平台

在现有字段来源上增加两类记录：

- `AcquisitionReceipt`：provider、endpoint、source_family、请求指纹、实际请求/缓存命中、耗时、预算占用、结果状态、原始内容引用、观测覆盖级别。
- `FactObservation`：证券稳定 ID、字段语义、数值/单位/币种、报告期间、数据生效时间、公开时间、本系统首次见到时间、解析时间、修订、来源片段、转换版本。

并非所有字段都需要单独表行：全市场日线仍以批次 manifest 为主；财务关键数字、公司行为、冲突字段才细化到单元格。统计血缘采用 `dataset / field / row` 明确粒度，避免全量行情逐单元格存图的膨胀。

严格区分三种读取：当时系统确实观测到的历史、按可靠原始发布时间重建的历史、今天最新修订的研究。重建可以做探索，不冒充当时系统实际使用过的数据。

同日字段合并还要核对定义：PE-TTM、静态 PE、动态 PE 不能混；单季、年初至今、TTM 不能混；合并口径、母公司口径、币种和股份基数要一致。价格相同不代表复权口径相同。

### 5.2 多源使用方式

| 已有源组 | 应承担的角色 | 必须防止的误用 |
|---|---|---|
| ZZShare / Baostock / Tushare | 核心行情、证券历史、财务与估值按实际端点能力供应 | 不把全部端点都标作严格 PIT；权限未满足就明确 unavailable |
| 腾讯 / 新浪 / eltdx / tdx_python | 报价、执行事实与行情交叉检查；历史能力逐端点验收 | 实时报价不能反填为历史已知；TDX 多适配器不自动算多个独立源 |
| Mairui / Moma | 在原生总额度内填缺、补充可验证字段 | 不按端点各发一份额度；先校单位、日期、账号权限 |
| 东方财富 / 同花顺 / AkShare | 资金、板块、财务和行情的有界补充 | AkShare 包装的同一上游不能算额外一票，也不能绕过上游冷却 |
| 问财 / 妙想 | 按策略版本保存参考、独立后验、发现覆盖差异 | 不回写正式候选；没有真实主力资金就不用量价代理冒名替代 |
| 巨潮 / 财联社 / 百度 | 权威正文、事件发现、背景检索分工 | 标题不是确认事实；新闻转述不是独立原始证据 |
| TickFlow / 集思录 / easy_tdx / mootdx | 对应品种或协议的可选能力，配置、许可与小样本验收后启用 | 不为“全用上”强开旧适配器；可转债/ETF 不套普通股票执行规则 |

源状态统一为 `SUCCESS / EMPTY / PARTIAL / NOT_YET_PUBLISHED / RATE_LIMITED / FAILED` 等机器码。只有明确查询覆盖、分页完成、发布时间边界满足的 EMPTY 才能表示该范围内没查到记录；任何 FAILED 都不能写成“没有事件”。

补跑按消费方缺口排队：正式必需字段 → 持仓风险与结算 → 候选研究 → 外部参考 → 探索。每个请求绑定一个 gap；补齐后取消剩余请求。相同问题单飞合并，失败源只做有限冷却探测。

保留原有限额，不提额：Baostock 继续单连接串行、项目默认 45,000/日、用户规定硬上限 50,000；Mairui/Moma 继续原生总预算。源家族预算是附加上限，不以抵消多层计费为由取消原生安全门。跨主机调用若出现，必须统一准入或明确单机独占；现有文件锁不能声称跨主机互斥。

验收：同上游包装不重复投票；重试分页计费可解释；99% 总覆盖不能掩盖关键字段 0%，也不因无关参考源失败阻断正式选股；健康接口仍然只读缓存。

### 5.3 原始归档与修订影响

允许保存的响应按内容哈希归档，保存解析器版本；URL 凭据剥离，账户材料独立权限。按供应商条款设置保留和再分发限制。不能保存原文时记录 locator、摘要校验值和“不可完整重放”，不虚称离线重建。

新修订先找受影响字段、run、论点和模型账本，再生成 `RevisionImpact`：数值改变/名次改变/成员改变/风险改变。原 manifest 不覆盖；修正重算使用新 revision，并保留“当时所知”与“事后校正”两套口径。

## 6. P0-B：让模型净收益真正成为可用证据

这是策略进化能否产生实际价值的前置，不是增加一张净值曲线。

1. **公司行为覆盖合同**：先做模型持仓与真实持仓，不扫全市场全文。记录登记日、除权除息日、到账日、每股权益、实施/预案/取消、更正和覆盖区间；区分权益应收与现金到账，防止除息日净值虚跌或现金提前可用。财务接口可探索 [Tushare 分红送股](https://tushare.pro/document/2?doc_id=103) 的日期字段，仍须当前账号权限和实测验证，巨潮实施公告作核对。
2. **完整性不是一个手工布尔值**：`corporate_actions_complete` 由覆盖凭证与处理结果推导；没查到、没接入、查失败分别表示。未知事件只阻断受影响账本区间的证据，不牵连其他合格账户。
3. **不可支持的事件不硬算**：送转零碎股、配股、合并换股、退市结算、差异化红利税等无法验证时标记事件缺口；现金未到账不能加仓。复权价格上涨不另重复记一次红利收益。
4. **执行事实落库与恢复**：保存确切日期的 raw OHLC、可交易状态、涨跌停和量纲。调度晚跑与“目标在执行前未登记”分开：前者若有执行前目标和对应日期可靠数据，可按原模拟模型重算；后者只能 backfilled。都不将历史模拟成交称为实际开盘成交。
5. **有界队列要公平且可见**：现有 160 标的上限保留资源约束，但超限项进入持久队列，持仓标的优先，报告 pending/covered/excluded；不能按排序静默遗漏后宣布整体完成。
6. **版本变更不能污染连续账户**：连续账户保留真实政策切换历史；估计新政策增益另建同资金、同初始持仓、同时间的配对评估分支。跨版本遗留头寸不能仅换 `policy_hash` 就算新版本独立证据。
7. **真实账户保持可选增强**：新增用户确认的现金/费用/权益导入合同、预览、幂等、水位和逐项勾稽。资金未知继续证券子账，不能自动猜余额。全账户外部流只认入金/出金等，买卖不算外部流。

真实收益差异输出固定桶：持仓价格、买卖与费用、外部现金、权益事件、估值时点、遗漏/重复、暂不能解释。优先输出金额勾稽；没有期间现金流水不输出假的 TWR。

验收：除息日有应收权益、到账日现金变化、重复事件、晚到修订、停牌、涨跌停、目标晚登记、执行事实晚到、超限排队、政策切换均有夹具。任何缺口不被计成 0 收益或 verified。

## 7. P1-A：从正式候选自然进入持仓研究

### 7.1 最小产品链，不先造大图谱

只新增一个长期容器 `ResearchCase`，以稳定证券 ID 或明确主题为 subject；关联多个既有 `foliant_runs`。用户换会话、模型或前端，Case 不变。DSH 负责执行会话；Foliant 拥有研究状态；Nexus/Web 展示；Platform 继续提供既有身份与插件投影。本轮不要求改其他仓库。

一份 Case 的最小内容是档案引用、待验证问题、证据集合、草稿/已锁定论点、到期检查和结论状态。先服务**持仓、最终 TOP5、用户主动指定标的**，每天其余 TOP15 只生成确定性研究问题，不批量调用 LLM。

入选到问题的映射示例：低估值→利润含金量与价值陷阱；主力资金→资金定义、持续性与价格反应；低价擒牛→低价是否伴随持续经营/股本风险；小市值→流动性及集中风险；净利增长→基数效应、扣非与现金流。

### 7.2 证据与论点分开

证据对象至少有原始内容引用、页/表/行定位、时间、修订和解析状态。Claim 分为事实、计算、推断、待核实；数字由工具提供或受控公式算出。模型提出 Claim，服务端检查期间/单位/引用/重算。确定性校验不能证明自然语言因果关系，因果解释标“候选解释”，重大矛盾交人复核。

论点以版本追加：Agent 起草，用户确认锁定；以后保留原文并提议新版本。每条支柱有预期变量、反证、截止日和 next_check。缺市场一致预期时明确缺失，只比较“我上次的判断与新事实”，不能伪造市场共识或 priced-in 百分比。

状态拆开，不堆成一个置信分：

- 覆盖：complete / partial / failed；
- 时效：fresh / due / stale；
- 结论：supported / watch / abstained / incomplete / conflicted；
- 用途：research_only / review_ready / blocked。

主体不同、数据用途不同，必要字段和时效策略不同。旧论点失效不能撤销已经发生的成交；缺论点不阻挡硬风险减仓。新重大风险即使不在旧支柱内，也必须生成紧急复核事项。

### 7.3 有界调查与注意力队列

对持仓异常波动，先判断相对指数/行业的偏离、权益事件和停复牌，再检查公告/财报/行业/宏观等固定渠道。不因普通小跌或转述新闻无限研究；没有确认原因就明确“不足以归因”。

每天注意力最多展示 5 个问题：持仓硬风险与重大冲突 → 持仓论点过期/催化剂到期 → TOP5 必要证据缺口 → 其余研究。将相同证券/证据修订合并，历史价格涨跌不自动成为论点被证伪的唯一标准。

新增收益最直接的输出：**为什么要关注它、原来判断有没有变、缺什么才允许继续研究、今天最该复查哪几只。** 深度报告按需生成，默认短结论加可展开证据，不扩张通知长度。

## 8. P1-B：把“每周问模型”升级成真正可检验的策略学习

### 8.1 验证协议按任务分型

| 类型 | 正确目标与对照 | 不可拿来替代的证据 |
|---|---|---|
| 横截面因子/五策略 | 历史可投资股池、按日分组、行业暴露、RankIC 与成本后组合对照 | 仅从今日 TOP15 反推过去全市场有效性 |
| 技术择时/基因组 | 同入选池的有信号/无信号、触发频率、时间外收益与未成交率 | 把全市场 beta 上涨当形态贡献 |
| 融合/账户政策 | 冻结候选、初始状态和执行模型，比较不调整、受控调整 | 仅看某策略单独赚钱就增加融合权重 |
| 新闻/论点研究 | 必要证据、期间、数字、预测裁决和弃权质量 | 拿 5 日涨跌判定多年业务论点真伪 |

先实现一种端到端协议，再扩展类型。新增全市场探索需要历史 universe 和未入选对照，避免把现有 TOP15 条件抽样误标成通用因子证据。

### 8.2 将尝试预算与统计搜索预算分开

复用 experiment 表，增加 `search_episode_id / hypothesis_family_id / protocol_id`。保留失败和重复，不通过改名开新家族重置预算。

- `attempt_count`：编译、请求、执行重试，用于资源与稳定性；
- `unique_candidate_count`：规范化公式、参数、股池、执行/成本模型等不同设计；
- `evaluation_count`：实际查看过指标的次数，包括换窗口、种子和反复检查；
- `holdout_access_count`：受控评估数据/标签的接触记录，预先预算、审计污染。

确定性重试可复用结果，不重复当独立候选；但随机重试、看过反馈再修复、换窗口不能借同名去重抹去搜索成本。不同表达式收益相同只能标相关/冗余，不凭此消除试验次数。

当前“每假设终身 8 次”作为初始安全上限继续保留，先修正分类与预算消耗口径，不在这轮擅自扩大预算。下一阶段是否放宽由已记录的有效探索率决定。

### 8.3 补真正的评估与晋级服务

冻结协议后，隔离评估器实际计算配对收益并写 `EvaluationResult`，绑定候选、输入、执行规则、代码/运行环境、测试窗口和预算。`consume_holdout` 必须消费这份真实结果，而不只是把批次改成 retired。

训练端没有受控标签访问权限；最终批次在看到结果之前登记，评估前先占用/封锁，崩溃恢复不能让另一候选再试。已打开结果的批次始终留污染/已消费记录，不因事务失败变回“从没看过”。公开市场的未来价格不可能对所有人永久保密，因此只能承诺受控评估访问和流程审计，不能宣称无人具有外部知识。

统计改进首先是正确命名和稳健性：现有不重叠区间改称 nonoverlapping_samples；按日期块处理横截面相关和序列依赖；预登记主要指标、检验时点与家族预算；小样本返回 insufficient_evidence。DSR/PBO/CPCV 是可选协议，不给每个任务机械套一套，也不把一个正下界当所有依赖下的统计保证。

三个政策对照逐步接入同一评估入口：不改政策、确定性控制器、LLM 提案加同一控制器。初期先比较政策差异、拒绝理由、换手和成本；成熟净收益后才能讨论 LLM 是否增加选股收益。

### 8.4 策略健康与更新频率

每策略版本分别显示数据、信号、执行、组合四类健康；市场状态先作解释和分层评估，不由 LLM 宣布“牛市”再加风险。

- 数据硬错误、执行规则不支持：即时阻断受影响策略/候选；卫星名额按原规则归还核心。
- 短期回撤或样本不足：警告/观察，禁止增加风险，不凭几天表现自动停策略。
- 确定性降级：预注册持续阈值、迟滞、冷却与恢复标准；保存每次状态转移原因。
- 参数提案：保留现有周度委员会，不增加每日改权；成熟样本不足则保持原政策。
- 新公式/新因子/新模型：独立版本、隔离研究与明确晋级，不允许 LLM 原地改特征目录。

LLM 产物记录真实调用结束时间、模型解析身份、Prompt/工具合同版本、fallback 链。今日生成的情绪/观点不能回填为历史预测。历史正文抽取可探索，但抽取产物与原始事实的时间分开，严格回放只用当时保存的产物或验证过的确定性事实。Prompt 中写 as-of 不解决模型参数中的未来知识。

## 9. P1-C：组合层先解决“值得换吗”，不增加 Alpha 分

合并现有 optimizer、风险、预览的输入版本，生成 `PortfolioRiskSnapshot`。先用可重放的行业、相关簇、流动性、集中度与可卖数量；不第一步就建设全套 Barra 式因子风险模型。

加入**不交易区间**：在硬风控不触发时，分数小变化、预计费用较大、仓位变化不足一个合规单位，优先保留“持有不动”方案。买入分与预期收益不是同一量纲，不能直接用分数差减手续费；无可信增益估计时，只展示费用、偏离和风险变化，不伪造“净增益 2.3%”。

压力情景先固定 6 类：费用/滑点翻倍、流动性减半、买入涨停不可成交、卖出跌停不可成交、晚一交易日执行、相关性集中。明确哪些情景替换执行、哪些替换风险假设，保留同一候选与初始状态。

当前“去某赛道”是从名单机械删成员；新增真正的移除赛道后重跑融合，保留原机械对照但改清名称。完整冻结的提名集不足时不生成伪重跑结果。两者回答的问题不同。

正式、风控后、实际、不动四条路径只在有足够持仓/现金/交易事实时比较。各阶段差异有交互、顺序依赖，不默认加总成唯一因果归因，更不能把“实际少赚”自动归咎用户。

跨行业共同假设先做用户确认标签和关联资金暴露，不把它说成预期损失或自动缩仓系数。若要升级为硬约束，须另有已确认的参数和回测/前向协议。

## 10. P1-D：真正测试 Agent，而不是只测试接口

保留当前零 token 的合同测试；新增单独的实际模型评测入口，不能把二者成绩混在一起。

首批 24 个去敏 A 股案例，四组各 6 个：数字检索、正式/参考边界、持仓研究、账户/导入预览。每案指定必需证据、允许结果、禁止行为、时间、调用和费用预算。另封存一组不参与调 Prompt 的案例；例子来自已结束任务或人工合成，不上传私人流水。

评测三种配置：当前流程、精简的人工编制任务流程、Agent 临时生成流程。沿用同模型和工具集，必要时分别报告流程与工具可用性差异，避免把“多给了工具”算成模型进步。默认只启用经验证的任务流程。

硬门：正式名单内容一致、权限零越界、未来证据零接纳、关键数字可重算、必需字段缺失时不伪完成。软指标：证据召回、支持关系、合理弃权、冗余工具调用、恢复成功率、端到端耗时、实际 token/费用。自然语言表述和合理工具路径允许不同。

扰动包括单位变换、季度/累计混淆、两个不同源转述同一公告、NULL、分页缺页、旧快照、供应商超时、模型 fallback、文档内提示注入、任务恢复、导入水位变化。关键案例至少重复 3 次检验随机性；温度 0 不等于可复现。

发布按“变更影响到哪些案例”选择回归，不跑模型×Prompt×工具×所有历史版本的笛卡尔积。未验收的新模型可做参考草稿，不得输出“已核验研究结论”；纯本地正式选股不应因解释模型 fallback 而停止发布。

访问日志由 Foliant 可控工具入口记录，区分 API 准入、底层 HTTP、外部运行时报告、不可观测。无法观测的 SDK 子请求/任意文件读取不能报告覆盖 100%。研究证据落受限存储；普通日志仅不透明 ID、状态、耗时与计量，不保存 Prompt、持仓正文、鉴权 URL 或模型私有推理。

## 11. P2：判断校准、负结果复用与低成本运维

锁定论点后可附 1–3 条概率预测：事件定义、期限、结算来源、概率、歧义与缺失处理都在事前固定。到期分别 resolved / unresolved / void / disputed，缺失不能硬算错；未裁决比例单列，避免只展示有利结果。Brier 与简单基准并报；少量或高度相关预测不画成精确置信度保证。

负结果只记录机制、失败类型、输入边界和下次可修复条件；不能把一次噪声亏损写成永久禁忌。研究记忆分为外部机制笔记、已验证实验反馈、用户偏好、缓存，权限、TTL 与撤销独立，不因此恢复大向量库。

调度复用 jobs_hub 和 Run：同步结果 ready 才触发依赖，区分 waiting-data、partial、failed、expired；重要依赖先行、可选参考不阻断。源预计未发布只更新状态，超过截止/影响正式结果才告警；同一故障聚合，恢复有记录。

工作量默认预算为提案值，不修改现有配置：自动深度研究最多 3 个 Case/交易日、每 Case 最多 12 次工具调用和 1 次综合模型调用；多模型审核仅用于重要差异或发布验收。所有任务共享现有供应商额度，重试消耗预算。通过实际成功率与 token 成本决定是否调整。

周末重 LLM 继续避开 09:00–12:00、14:00–18:00；夜间以 23:30 收尾、24:00 硬截止为目标。启动预算必须考虑剩余时间，跨截止保存检查点而不是无限重试；不能以任务异步为理由绕过依赖或结束窗口。

## 12. 实施包、顺序与交付标准

| 包 | 范围与主要落点 | 完成的判据 | 依赖 |
|---|---|---|---|
| A 输入证据 | source contracts/governor、research_store、质量报告；访问回执、同源家族、字段语义与修订 | 固定夹具可定位错日期/单位/包装重复；跨源不静默拼错；预算和缺口可解释 | 无；复用 0.5.0 |
| B 结算可核验 | model_portfolios、decision_loop_jobs、model_ledger、账户导入合同 | 权益/原始执行事实/水位/连续政策证据通过；明确输出可验证与尚缺事实 | A 的相关端点合同 |
| C 持仓研究 | research_artifacts、应用用例、Case/Thesis、现有驾驶舱与任务 | 一只持仓从旧论点到新事件、反证、待办完整走通，不改 TOP 与成交 | A；不等待 B 全账户完成 |
| D 验证与进化 | research_governance、trial/holdout、策略控制器 | 一个假设完成登记→求值→隔离评估→拒绝/晋级；故障和污染也留档 | A、B；样本不够就保持政策 |
| E 组合与校准 | optimizer、account_action_plan、风险快照、预测裁决 | 不动/换仓成本比较、情景重放、版本归因；预测原尺裁决 | B、C；复杂风险模型延后 |
| F Agent 发布与维护 | agent evals、合同/工具入口、Run、遥测 | 真实模型过程评测与纯合同测试分开；恢复不重复副作用；发布回归能定位失败 | A 起即建设，每包复用 |

建议执行顺序：**A + F 基础 → B 与 C 的最小闭环 → D → E → 按实测结果扩展**。不是先把全部框架实现、最后再接一个消费者。

每包必须包含数据库/合同兼容方案（若涉及）、真实调用链、测试、可见结果、文档、关闭新功能的回退方式。仅有类、表、状态机或通过 mock 的漂亮页面不能勾成完成。

升级只追加 schema 与版本；旧 artifact 保留 legacy，不补造发布时间、论点、现金或证据。新表先写后读，读路径有 legacy 适配；不双写两套互相竞争的正式真相。大原文存受限内容归档，数据库存索引；运行审计按容量归档，正式决策引用的证据不随普通日志轮转删除。

依赖按锁文件、代码版本、解析器、工具合同、可选 worker 镜像摘要形成 `DecisionManifest`。沿用 Platform 既有发布/权限能力，不新建个人 NAS 的 CA 或签名中心；正式选择不因无关研究模板过期而全停。

生产发布仍需单独授权、备份与真实环境验收。可以直接启用已验证的工程能力；不能用“直接使用”豁免缺失事实、污染检测、原生源配额和增风险政策证据门。

## 13. 最小成功标准

下一版不以增加多少策略/页面计成功，而应实际回答：

1. 今天为什么能选、哪些字段来自哪个源、还有什么缺口？
2. 某个数字后来改了，影响哪些历史结论，而不是把历史直接改漂亮？
3. 模型收益是否包含权益、费用、未成交与现金，哪些区间还不能用于进化？
4. 持仓原来的判断是否仍成立，今天最值得复查哪几个问题？
5. 这次不动/换仓各要承担什么费用和风险，是否有足够事实比较？
6. 一条策略究竟试了多少次，改动是实证增益还是选择性展示？
7. Agent 换模型或工具出错后，仍能取对证据、承认缺口且不越权吗？

这比继续增加选股来源更有价值：来源已经足够多，下一步应让它们产生**可核验的数据、可持续的研究和能解释的策略改进**。
