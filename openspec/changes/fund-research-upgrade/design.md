# 基金数据与核算设计

状态：本地实现按本设计落地，使用与验证记录见 [使用说明](../../../docs/FUND_RESEARCH.md)。详细产品方案见
[调研与优化方案](../../../docs/plans/2026-10-15-fund-improvement-plan.md)。

## 数据流和职责

公开来源适配器 → DataHub 预算与缓存 → 带版本的基金事实及质量检查 →
基金核算与回测 → 应用服务 → HTTP、MCP、任务与 WebUI。

沿用 `data/sources/` 和现有路由；新增基金专用 contracts、收益序列和账务规则模块，
由统一应用服务编排。具体文件拆分在各阶段实施时确定，跨入口不得各写一套公式或原因码。
研究结果复用 `application/research_artifacts.py` 的版本化工件与 AI 附加解释模式。

## 规范对象

| 对象 | 关键内容 |
| --- | --- |
| 产品与份额类别 | 基金代码、内部产品 ID、份额家族、交易方式、资产类别、币种、基准、交易日历、有效期及来源 |
| 净值与权益事件 | 净值归属日、原始净值、分红/拆分/收益结转、公开时间（可为空）、首次观测时间、来源上游、修订与快照哈希 |
| 质量结果 | 请求区间、实际区间、缺口、完整性、新鲜度、状态及原因；功能开关与数据状态分离 |
| 账务事件 | 账户/渠道、申请/确认/到账/录入时点、金额、份额、费用、分红方式、批次、外部 ID、来源和冲正关系 |
| 定投事项 | 计划 ID、锚点、周期、应到期日、实际处理日、预算、状态与唯一键 |
| 研究及实验 | 输入快照、规则版本、已知时点、费用/日历/分红假设、资金到达计划、输出及质量报告 |

货币基金采用相应收益序列，场内与场外产品采用不同执行约定。金额与份额使用明确的
Decimal/数据库精度规则；不得将存储舍入和展示舍入混用。当前 REAL/DOUBLE 字段的迁移需先预览差异。

## 收益语义

单位净值用于按净值申赎；总回报序列使用已校验的权益事件或可解释的复权来源。
现金分红、再投和拆分按事件顺序处理，不能直接用累计净值替代再投收益。
组合边界内的买卖和分红不是外部资金流；账户外转入转出才影响时间加权收益的资金流调整。
XIRR 使用真实日期和现金流；无解、多解或短跨度不足时给出状态，不输出看似确定的年化数。

回撤从现金流中性的净值序列计算。日收益基于适用时点的份额、净值变化、费用与权益事件；
后台现有净值差实现作为统一入口的基础，不能把“当前份额乘净值差”当成已覆盖日内申赎的最终规则。
披露滞后基金可以进入带日期的资产估值，但不能混为当日已确认收益。

申购费计算基数、折扣、赎回费阶梯与份额精度以产品/渠道规则为准。
已体现在份额净值中的运作费只展示、不重复扣除。

## 时点和信任边界

比较带时区时刻；历史无时区业务时间按上海解释，海外市场依据产品日历。
决策只能使用当时可见的数据。没有可靠公开时间或首次可见历史的回填数据不得冒充 PIT 策略证据。
价格位置策略与估值策略分开，利用收盘后数据的信号移至规则允许的后续执行时点。
申购净值未知时保持待确认；最新公开净值不是该笔交易的成交回执。

源异常、部分历史、正常待披露、样本不足和功能关闭分别记录。东财直连与 AKShare 东财接口
共享上游身份；独立确认使用基金公司公开披露或已授权的独立数据源，不能把接口数量当来源数量。
AI 只能解释有来源的事实与计算，不提升数据状态，不改写真实账务。

## 迁移与回退

先建立规范和离线样例，再增加字段/事件存储，保留旧接口投影。
以期初余额加可核验后续流水迁移；未知历史保持未知。历史自动记录保留 `dca_auto`
等来源信息，提供逐笔确认或重建预览，不能批量删除或认定全部为真实成交。

新旧计算对固定快照出差异报告；历史实验保留旧版本，重算生成新版本。
应用层切换可逐入口回退，已确认账务只能通过可追踪冲正修改，回退不能丢失事实。
部署后验收单独记录版本和只读对账结果，文档提交不代表上线。

## 未采用的方案

- 整体引入 Qbot 或替换为 xalpha：与现有应用、权限、账本及依赖边界重复；xalpha 先用于隔离对照。
- 只改界面与增加 AI 角色：不能解决回撤、分红与确认日期错误。
- 最新行情作为失败回测的自动替代：破坏可复现性和历史时点约束。
- 最新持仓倒推历史或全部跨类型统一排名：会掩盖披露时差、样本和产品风险差异。
- 为等待 QDII 净值放宽质量门槛：正常待披露应保留状态，不能伪造今日成功。
