# 设计与边界

状态：0.5.0 实现基线。详细方案保留设计目标，实际能力与外部验收缺口见 `docs/RESEARCH_DECISION_LOOP.md`。

## 事实与动态状态

正式选择固定数据 manifest、策略/特征版本、代码/环境版本与决策时间。
上下文读取引用这份冻结工件；实时行情、当前持仓和 freshness 位于动态 envelope，
不能写回或改变冻结事实的内容哈希。

多源观测可在冻结前按字段语义和日期合成，来源选择保留证据。冻结后修订必须发布
新 generation，不因为在线主源恢复而改变旧 Run。

## 五条链路

- 数据：已有源适配 → 质量检查 → publication → QualityReport → 有界补缺。
- 研究：hypothesis → trial → evaluation → promotion，复用 Run/Artifact。
- 选股：统一可投资快照 → 本地三赛道 → 正式 TOP15/TOP5。
- 账户：机会 + 受权持仓快照 → 行动预览 → 人工真实成交/独立模型成交 → 对账。
- Agent：受权引用 → 用例工具 → 结构化结果/证据，不获得更大权限。

## 状态和权限

推荐 trial 状态：registered / running / evaluated / rejected / failed。
政策另使用 proposed / validated / scheduled / active / superseded / rolled_back。
状态不是同一字段：一次实验成功运行，不代表策略已经有效或获得发布授权。

日常政策控制器只能发布已批准参数空间内的变更；额外因子、模型代码、权限变化需要
独立评审和发布流程。研究 Worker 只读导出的快照，无生产凭据、无封存集、无宿主挂载，
有 CPU/内存/进程/时间/网络预算；不能把 Python 子进程当作任意代码的安全沙箱。

真实成交导入沿用 Nexus Review、水位校验和幂等提交；行动计划本身不生成真实成交。
个人上下文存储、缓存与引用解析都绑定主体授权，普通研究 token 不能读个人工件。

## 评价边界

信号 cohort 与滚动账户分开；费用/公司行为/未成交属于共享执行语义。
当前价格后验不回写为净收益，新旧结果都有 metric_version。
行情日期不等于发布或成交时间，回填结果不标记为当时已发布的前向记录。
有效样本考虑重叠区间，封存集按批次退役，统计结果不等于未来盈利保证。

## 拒绝的替代方案

- 一次重写全部存储/任务/前端：风险大且难归因，改用增量用例迁移。
- 冻结前也禁止数据源兜底：与多源可靠性目标冲突，固定合成规则与版本更合适。
- 全量引入重型调度/实验平台：当前已有 durable Run 与 Outbox，先扩契约。
- 让 LLM 自由生成正式权重/执行动作：模型提案不等于可交易事实或执行授权。
- TOP5 必须与 TOP15 前五不同：这是表面指标，不代表研究或组合价值。
- 所有改造先等数周影子：不符合使用需求；设施直接启用，未证明的新策略另受晋级门限制。

## 迁移与回退

每个实施包独立验证；新 schema 兼容扩展，新语义新版本，旧记录不静默改写。
正式读取指向单一已激活版本，发布原子 CAS，失败保留旧版本。
部署前仍需常规备份、合同/重放测试、任务空档与回滚路径；本提案不触发部署。
