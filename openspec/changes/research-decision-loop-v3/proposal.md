# 研究—账户行动—评价—进化闭环

状态：用户已授权实现，0.5.0 本地回归与独立 PostgreSQL 集成验证通过；不授权部署或券商操作。

## 动机

当前系统具备本地多赛道选股、版本化输入、工件重放、Agent preview 和周度政策调整。
主要缺口不是指标数量，而是信号后验与可成交净收益混用风险、政策证据和数值校验不足、
持仓行动与正式机会缺少清晰分层、研究上下文重复组装、健康检查计算过重。

## 范围

1. 修复政策提案边界并统一时间/指标语义。
2. 扩展已有数据合同和质量报告，保留有界多源补齐。
3. 区分信号后验、模型前向验证、真实账户及版本化收益对账。
4. 增加持仓感知的行动预览，不修改正式研究排名。
5. 建立实验登记、成熟证据、封存评估与可回滚政策生命周期。
6. 复用已有研究工件和 application 服务，改善 Agent 工具与 Web 工作台。
7. 为隔离的因子/模型研究提供可选扩展，不引入生产任意代码执行。

## 非目标

不恢复 RAG，不迁移生产数据库，不新增券商下单，不要求整体影子等待期，
不强制依赖 Qlib/RD-Agent/skfolio/Dagster，不在本次提案中更改生产配置或历史账本。

## 兼容性

- TOP15、TOP5 与外部参考保留；行业上限和用户策略偏好仍是初始政策。
- 新行为使用新版本，旧 manifest、旧指标与旧 API 经适配保留语义。
- 普通研究 Profile 不获得持仓读取；个人投资预览仍经过专属授权。
- 日常策略政策与重大模型/权限变更分开发布。
