# Design

## 1. 单一事实归属

继续使用 PostgreSQL repository、版本化 manifest/artifact、现有 Run 租约与 Outbox。
ResearchCase 组织长期问题；Run 执行一次工作；DecisionManifest 引用既有正式选择、政策、证据和风险版本。
三者不复制同一套正式结果。Capsule 是面向权限和上下文预算的投影，不成为第二个真相库。

## 2. 信任边界

供应商响应、网页、原文、模型输出与 Agent 记忆均是输入，不是指令或自动可信事实。
数据适配器提供获取回执和原始引用；确定性转换绑定单位、时期、语义及修订。
LLM 只能提出 Claim、论点草稿、假设和白名单政策提案；不能修改正式成员、发布时间、验证状态和用户锁定原文。

数据源预算保留原生硬门。上游家族识别增加附加预算与独立性说明，不能解除 Baostock 串行/日上限。
只承诺已接入入口的观测；未知 SDK 内部调用明确为不可观测。

## 3. 模型与事实时间

原始事实公开时间、系统首次见到时间、解析时间与 LLM 完成时间分别记录。
历史重建与当时真实记录分开。今天生成的观点不能变成历史预测。
缺模型解析身份/版本时标 unknown；不把模型别名、温度 0 或 as-of 提示词当成确定性与无前视证明。

## 4. 模型结算与实验

权益覆盖证据决定账本区间是否可核验，不能由外层调用方随意声明 complete。
模拟执行原始事实按日期冻结；错过任务运行不等于目标晚登记，恢复时分别处理。
新增政策评估从相同初始状态配对，连续账户保留切换历史；不把遗留头寸收益改标签变成新政策证据。

研究评估器与生成器隔离：冻结候选与协议，预留评估预算，隔离数据访问，产生不可变 EvaluationResult。
最终批次开启前原子占用，故障后幂等恢复；看到结果后的状态不得回退为未使用。
公开市场知识无法全局封锁，隔离承诺限定为受控评估器及流程，不宣称绝对盲性。

## 5. 用户与风险

Agent 不能代用户锁定论点；缺论点只影响研究完备性，不影响自主操作记录、止损或减风险提示。
反事实对照提供差异，不将机会成本自动归咎用户；现金/权益不全时不出全账户收益结论。
组合风险、研究状态与正式 Alpha 分数分别存储。任何基于状态的正式准入变化都须版本化规则。

## 6. 隐私与供应链

原文、私人账户与证据索引按主体授权，公共统计不含正文/密钥/真实连接信息。
内容保留遵守源条款，不能归档的材料声明回放限制。普通日志仅不透明 ID 和运行计量。
可选外部库先核许可证、锁依赖、离线验收；研究代码继续受限 DSL/隔离 worker，不开放生产 Python。
内容哈希是校验与寻址，不是权威来源或抗最高权限篡改的证明。不额外建设签名基础设施。

## 7. 拒绝的替代方案

- 多 Agent 投票产生正式候选：破坏既有正式/参考边界。
- 为统一对象名新建三套 Episode/Decision 账：重复 Run 与 artifact 职责。
- 立即全量数据湖/图数据库：缺少本地性能证据，先用关系索引与有界归档。
- 单一置信分乘仓位：混淆数据缺失、模型不确定度与投资风险。
- 把所有硬门交给 LLM judge：无法保证数字、时期、权限与副作用约束。
- 所有功能等前向样本成熟才启用：不必要；只限制增风险研究晋级。
