# 实施与验证清单

以下均为后续工作；设计阶段没有启用推送或改动生产配置。

## 1. 每日必报（先交付）

- [ ] 1.1 提取原生持仓、主数据分类与账户水位的纯读取服务，确定同市场证券身份；输出个股数、ETF/其他数、上下界、最后变动与最后核实日期；收敛旧界面中的 20/25/40 各类提示，区分用户上限与独立集中度指标。
- [ ] 1.2 把现有退出规则、唯一动作裁决和组合保护接到全持仓优先清单；输出原始/最终动作、触发依据、证据缺口、可卖性、名额影响；未知浮盈亏和交易日期不得置零。给纯读取路径显式禁用写决策信号。
- [ ] 1.3 在原生任务中心加自然日义务、当日越线事件、租约/领取、同日重启补发及次日欠发留痕；共用既有私人报告渠道，沿用交易时段即时告警边界。默认上海时间 14:30 和 15:10，实际设定写入外置配置文件。
- [ ] 1.4 接收实际路由结果，保存稳定报告键、渠道/分片、接受与归档；区分明确拒收、投递结果未知、只补档。正文冻结后只有同一载荷重试，另建 attempt 引用；支持以不同子键先发“账户待核”、恢复后再交付已确认报告；旧稿未受理与已受理或在途未知采用不同换版规则。
- [ ] 1.5 本地模拟 15/16 边界、混合品种及同码、周末/节假日、晚导入、同日降回 15、跨午夜、账户旧快照、无行情、无 LLM、无可卖量、百只以上及持仓中途变化。并发原生/备援只收一次；不发送真实测试通知。

## 2. 各时段内容与数据质量

- [ ] 2.1 实现统一事实包：行情截止时间和范围、账户水位、证据与冲突、正式排名/复核、持仓最终动作。优先复用已有数据仓，缺同刻成交额、真实涨跌停规则或可靠分类时如实显示。
- [ ] 2.2 为晨报、选股、持仓、盘面风险、盘后复盘分别设计首屏；按渠道预留必报字段。实际最大长度渲染贯穿原生 renderer、路由压缩、受保护 CLI/HTTP（如消费）、归档与重复/部分投递，检查截断后正文仍正确。
- [ ] 2.3 Web、既有个人 Skill/受支持 CLI 与通知使用同一报告标识；私有详情检查权限、手机宽度与筛选。抽样比对标题与正文、历史与当下、组合与单股。
- [ ] 2.4 盘后对账证券主数据、行情覆盖、行业映射、账户核实时间、基金净值确认与参考源语义；按决策影响排序补数据，记录补采预算、退避、实际覆盖提升以及仍受阻的建议。

## 3. 左侧、复盘与自然验收

- [ ] 3.1 冻结第一版观察参数、交易日历和分母；生成观察→企稳待验证→暂停/失效的记录，标出样本外的新候选和未入选原因，验证不改变现有正式排名或生成真实交易。
- [ ] 3.2 成本与基准齐全时做同日期、同预算、可成交的前向对照和滚动时间外验证；提供最不利波动/换手/回撤、行业敞口、反弹误杀、样本数和不可重放率；独立日期或数据不足就维持研究状态。
- [ ] 3.3 用历史时点截断后重算，检查未来财报、修订、复权和收盘信息不会倒流；对历史冻结不足的批次标不完整，不用当前行情弥补。
- [ ] 3.4 获授权发布后，以自然交易日及自然休市日的应发账本、渠道原稿、实际载荷及回执验收；分开记本地验证、生产就绪、自然送达、终端展示与策略效果。关闭影子策略或回退展示不会清除当日回执或丢掉日报义务。

## 4. 早盘正文与问财应用

- [ ] 4.1 在同批指数快照保留市场代码、有效点数、昨收、开盘与供应商时刻。盘前走已核收盘，盘中区分缺值与真实零。为旧快照保留仅涨跌幅的显示。
- [ ] 4.2 将早盘固定摘要、独立午报、风险通知等真正发送的正文接到统一指数展示。用含最大风险行和长名称的实际载荷贯通路由、归档和预算，检查五指数、优先待办与行情时间。
- [ ] 4.3 对问财各组保存取样时间和冻结前 K，生成独有/重合和本地验证结果。单列异常、零命中、未成熟和复用，按相同有效日期回放 1/3/5/10/20 日表现，发布每组样本数与估算成本后的增量。
- [ ] 4.4 在隔离材料上验证早盘只数、已持仓与非持仓筛选、拆分后成本待核、无候选和后到的问财样本。验收 09:00、09:45、10:05 和盘面风险各自使用当时可见的字段。
