# 股票研究与每日持仓决策设计

**先交付每天一定看到的清仓建议，再验证更早发现机会的左侧名单。** 两项共用行情和账户事实，但选股排名不替个人账户下指令。下文的时刻是上海时间，新增阈值、时刻均为提案；例子使用虚构持仓。

## 1. 现有代码能做什么，哪里会误导

## 2. 市场 → 行业 → 个股：如何使用已有数据

以 **2026-11-03** 为设计检验日。公开的[同花顺午间快讯](https://yuanchuang.10jqka.com.cn/20261103/c681394318.shtml)报沪深上涨/下跌 3,303/2,135，创业板指 −0.94%；同源[收盘快讯](https://yuanchuang.10jqka.com.cn/20261103/c681399821.shtml)报 2,108/3,309、创业板指 −2.73%，沪指 −0.82%，全市场成交额较前一日缩量 4.43%。由此只能推断**午后下跌扩散、成长侧承压**；不足以判断某只股票底部已经形成。不能把收盘结论塞进午间回放。对照本地应保留各自的样本、停牌与平盘定义，不能硬拼一致。

| 决策问题 | 首选已有数据 | 缺口与处理 |
| --- | --- | --- |
| 大跌是局部、孤立还是连续？ | 同时点核心指数、沪深 300 前几日走势、A500 成分及涨跌中位数；已有 PIT 日线另算收盘全样本广度 | 并列范围、分子/分母、时点。成交额盘中与前一交易日同分钟比，收盘与收盘比；缺同刻历史则标未知。缺成分或广度时给指数事实，不给市场抄底结论。 |
| 哪些行业放大了账户风险？ | 同批行业分类、相对强弱与个股市值；基金已有季报穿透 | 分开“直接持股”和“已披露基金暴露”；行业未知不摊给其他行业。只在同样本/同分母下比较变化，主题消息单独标出处和首次观测。 |
| 个股是估值回撤还是基本面变了？ | 冻结复权 OHLCV、回撤/ATR、量价；同行业估值、已公布的盈利/经营现金流与公告；记录财报期和发布时间 | 负盈利不拿低 PE 加分；缺量不说缩量、缺覆盖不说无利空。复权序列用于比较，报价/触发位按当时可交易价格口径转换。旧公告更正追加版本。 |
| 建议在该账户是否能用？ | 已导入持仓、流水、水位、当批报价及风险、组合保护；预算和已核实现金分开 | 先补品种分类、持仓对账时间、可卖量/成交确认来源；无法获取就说“待核”，无须等齐才发日报。场外基金继续按确认净值及披露日。 |

数据补强按**改变了多少条决策**排序：先记录每个阻断原因、受影响标的与时段；优先复用同批缓存或补采缺字段，遵守 DataHub 的配额、去重和退避。已有源不能稳定满足时，才评估增加供应商。每个字段保留来源、市场日期、首次可知时间、单位/复权、覆盖率；冲突能核验则核验，否则并列或留空。盘中不做全市场逐股二次采集；盘后派生全市场宽度、行业分位及历史基线供次日使用。

## 3. 左侧偏好：先发现，再决定是否值得冒险

初版是可重放的研究策略，和正式名单并列展示。每期从同一 manifest 的合格全集开始，排除上市历史过短、流动性不达原门槛、重大风险、时点不合格等标的。已涨上去才满足趋势追认的票仍可在正式榜，本侧池不为它加“左侧”标签。

| 给用户的状态 | 必须能解释的条件 | 允许的下一步 |
| --- | --- | --- |
| 左侧观察 | 相对自身与同行估值有支撑，基本面未见已知证伪，出现显著回撤或相对行业超跌 | 列出价格区、支撑理由和一个推翻条件；不能仅因股价低、跌幅大或 RSI 超卖入选。 |
| 企稳待验证 | 上述理由仍成立，有可观测的抛压收敛：如低点不再下移、成交量收缩且行业相对强度改善。用实际量价字段，不能照搬现有 RSI 布尔值。 | 只进优先跟踪；初版不授权试仓。晋级后也须有效报价、盈亏比、预算、交易与持仓限制全部通过，才允许出现条件式小仓预览。 |
| 暂停／失效 | 公告证伪、失效位触发、放量破低，或有效期到但未证实；大盘连续杀跌可暂停全池的新增风险 | 区分“论点已坏”“盘面不宜”“证据缺失”，说明何时再看。已持有的票回到持仓唯一动作裁决。 |

**可证伪的首版实验**（仅供影子对照，非生产参数）：以同行业正 PE 从低到高分位 ≤40%、最新可知的经营活动净现金流（TTM）为正、距近 60 个交易日最高收盘回撤至少 12% 为观察模板；行业不可比、历史不足、财务缺失则放弃此模板。观察后连续两根完整日线未破观察日低点，最近三日均量低于此前不重叠的 20 日均量、近三日收益不低于同期行业中位数，方标“企稳待验证”。观察日起最多 10 个交易日，出现已知证伪或收盘再破观察低点作废。排序先证据完整性，再同行估值分位、回撤与抛压变化，最后用固定证券标识破同分；冻结策略版本，不边看结果边调。分行业模板独立验证，金融等经营现金流不具可比性的行业不套通用模板。结果可为零，不强塞满五只。

持仓建议另走现有组合保护：若只有浮亏扩大而原论点仍在、市场普跌、个股无新增硬风险，标“回撤复核”，不可写成“买入理由已坏”；若触及已确认硬止损或论点证伪则优先退出评估，不用左侧偏好延后止损。超限期间新个股只观察或列条件替换；先确认原股实际全数卖出，再刷新名额、现金、报价与风险。持仓未超限也不自动放行加仓。

## 4. 个股超过 15 只：每日清仓建议保证

1. **数什么。** 在私人证券账户同一水位，以市场＋正规化证券身份去重，合并重复批次，已确认净数量 > 0 的个股记为 N；清仓行、现金、基金、ETF、LOF、债券均不算。场内 ETF 单列只数，不因双账本重叠重复统计。复用证券主数据；仅能证明“非股票基金类”时不擅称 ETF。没有价格不影响只数；缺数量、品种不明或账户未能读取单独列出。数据源导入/对账水位与最后变动日期分列，只有持仓长时间不变不是已自动对账的证据。
2. **何时发。** 上海自然日 N > 15 才产生强制日报；N = 15 时没有超限义务，独立风险提醒照常。交易日 14:30 优先随原生尾盘报告发出；休市日 14:30 仅该日报运行，沿用最近有效收盘事实并标日期、“下次开市前复核”。15:10 检查当天必报回执。当日晚导入首次确认越线立即补发；服务重启先恢复当日欠发。流水无法证明曾经越线不编造历史。已确认越线后若发送前已降到线内，仍交付当日结项“现已回到 N 只，无需超限清仓”，不得推荐已卖标的。跨日漏报留审计，不连发过期指令。
3. **不因缺数据漏报。** 对未知记录给下界 L（确定个股）/上界 U（含可能个股）。L > 15 必报，缺行情、可卖量或 LLM 不妨碍交付。L ≤ 15 < U，或上次确认超限、本次账本不可用，发“持仓数待核／上次确认超限”的日更复核，写明缺什么，不把它计为已验证清仓建议或达标。U ≤ 15 时正常不触发。完全无可信历史则记录数据故障，不报空仓；恢复后重算。
4. **先清谁。** 覆盖全部活跃个股，不用只数上限或通知 Top-N 截断分析。按已证实的硬止损/论点失效 → 同行业暴露重复且证据相对弱 → 持有理由过期或弱势持续排序；同层按证据完整度、风险贡献、固定证券标识排序。仅凭持有时间长、浮亏或没入 TOP15 不构成清仓理由。依次列“优先整只退出”“条件退出／待核”“只减仓”和“不动”；每只给事实、反证/阻碍、复核时点。证据足够才点名；没有合格项仍发“可整只退出 0，只数仍超 K，首要待核……”。
5. **只数与执行分开。** K = N − 15 是待收敛只数。清掉一只才释放一个名额，部分减仓释放 0。核验可卖覆盖全部数量、市场状态、T+1、停牌、跌停流动性、组合换手及最终动作；不能核实则仅给退出优先级，不给确定数量/成交价。默认先沿用已有单次最多 3 个 sell、8 项动作、估算 10% 换手和同触发限制；同一交易日多次计算不能重置额度。保留原始风险和降级原因，只有独立的真实成交/导入能改变只数。
6. **发得出，也知道哪里没发出。** 用（私人账户、上海日期、个股超限日报）作为稳定业务键，渠道/分片为子键，持仓水位只作版本而不是新建日报的理由。先落完整报告和待发记录，再由原生任务领取。首次对渠道尝试前检查持仓水位；若已变化，用新版本替代未发送稿。若所有尝试均明确未被接受，允许作废旧版并关联更新后的结项，不复用旧载荷键。一旦任一片已接受或结果未知，保留原稿和发送状态，私人详情追加新水位、撤回失效建议；不得拿同键改稿或重复整份发送。“只数待核”是独立子类型，不占正式日报键；同日恢复确认后仍可交付正式稿。尾盘合并版必须含清仓首屏且获得指定私人渠道接受，普通盘中报告、监控静默、另一个渠道的成功都不能抵账。保存每片状态：明确未发送/被拒可在当日退避重试；已接受不重发；超时不知是否接受先查渠道回执或同键幂等，无法核实则标 unknown 并以运维告警处理，不声称必达。归档待修只补档。后台同时查看应发、接受、漏发、部分、未知；渠道接受不代表手机已读。

## 5. 一天的信息如何变短又不丢事

| 时段 | 首屏要回答的问题 | 后续内容 |
| --- | --- | --- |
| 盘前 | 哪项隔夜事实会影响已有持仓？今天等待哪个条件？ | 公告与新闻分开、出处/时点就近标；不拿昨收当今价。 |
| 正式选股 | 今天出了哪一批？哪只是左侧观察，哪只仍属趋势候选？ | 保留 TOP15/TOP5 原序；精选写入选原因和不追条件。问财/妙想单列核验状态，未验证不投票。 |
| 早盘／午间 | 相比上一时段，广度和行业变了什么？我的哪笔判断要变？ | 持仓动作优先、只列有意义的变化；休眠观察不重复刷屏。硬风险另走现有即时渠道。 |
| 尾盘／超限日报 | 个股几只、超几只、先看谁、能否整只退出？ | 强制项不被“无变化”抑制；首屏最多三个优先项，全部硬风险和其余候选在有序续页或已授权详情可查，不静默截断。 |
| 收盘与周复盘 | 哪些触发、哪些后来失效，按当时信息本该知道什么？ | 区分观察、建议、券商成交、未执行原因和实际结果；正常未成熟与失败分列。 |

**纯文本首屏样例（模拟；只展示两只候选，不代表真实持仓）**

> 14:30 ｜ 每日清仓建议
>
> 个股 18 / 15 · 超出 3 只　场内 ETF 2 只（另计）
>
> 优先清仓：甲公司 · 已公告的客户流失推翻持有理由；可卖数量已核，本次可整只退出。
>
> 条件退出：乙公司 · 与第一大行业暴露重复，最新经营数据转弱；可卖数量待核，暂不计名额。
>
> 若甲实际清仓：18 → 17，仍超 2 只。盘面转弱，新左侧候选只观察。
>
> 行情 14:29 ｜ 账户最近核对 13:50 ｜ 下一次看收盘是否再破低点。

降级样例：“个股 16 / 15，ETF 3 只另计。今日可确认整只退出 0 只；甲公司为首要复核，昨收已破失效位，今日日内报价和可卖量尚未核实。仍超 1 只，行情恢复后复核。” 休市样例：“周日｜个股 16 / 15，仍超 1 只。沿用周五收盘的甲公司退出观察；今天不开市，开市后先核报价和可卖量。” 普通报告随渠道选择短标题、换行与有限强调；纯文本不依赖颜色、表格或可点击按钮。私人详情沿既有鉴权打开，不在通知链接放账户标识或持仓正文。

**标题不能与正文打架。** “组合仓位不变”可以与个股风险并存，应写“总仓位维持｜2 只个股优先复核”，不用笼统的“不动”。每只只有一个最终动作，原始触发另列。正式排名、研究复核和账户动作并排：如“正式第 1｜复核：不支持新开仓｜原因…”，非持有人不出现“卖出”。复核还没完成时标待复核，后到的结论只进下个时段的变化或私人详情，不伪装成原始发稿时已知。

**以实际发出去的正文设计。** 原生摘要和路由存在先后两次压缩，不能在已有 8 行末尾追加清仓段。预留标题/前三行给超额、优先退出、阻断或可释放名额；无动作时保留原因。超过渠道正文预算，稳定记录有序续页或鉴权详情；危急事件保持原认证发送者。真正的业务成功需要指定渠道接收**含必需字段的实际载荷**。同键不能换正文重跑：重投保存同份原稿，用 attempt/retry_of 区分投递尝试，已收片或仅存档失败不得再次发送。

## 6. 其他模块的改进与优先级

| 范围 | 设计决定与可交付结果 | 如何发现改善或回归 |
| --- | --- | --- |
| P0 数据与调度 | 对日历、个股主档、净持仓/流水、行情、财报、正式批次、当日建议、投递逐环节显示最近应到/实到与影响；同一水位批量取价。休市、未披露、配置关闭、超时、部分返回和程序错误用不同状态。 | 一次只补失败字段或任务；先覆盖 15 只边界跨越，再看各时段覆盖率与最慢阶段、供应商超时和预算。任务运行但无有效业务产物不得显示全绿。 |
| P0 账户与风险 | 补最近一次对账标记、证券身份冲突队列、可卖来源及行情有效期。账户与市场不共享一条模糊动作；有风险的 ETF 仍告知，但不会为了腾个股名额推荐卖 ETF。 | 样例验证证券别名冲突、同码异品种、旧流水、数量未知、半仓卖出、盘中持仓变化、缺价和极端行情。导入未发生不把建议当成交。 |
| P1 研究与复盘 | 复用 [决策闭环](../../../docs/RESEARCH_DECISION_LOOP.md)、[精选归因](../../../docs/SELECTION_PERFORMANCE_REVIEW.md)。每个结论绑定榜单/策略/时点、财报可知日和复权版本；补全失效或未执行原因。 | 同冻结批次比较正式 TOP5/TOP15、原影子与新左侧；1/3/5/10/20 日观察分开，评估对应周期的名额占用、首次触发率、最大不利波动、换手、回撤、扣费用净收益与相对基准收益。未成熟、缺标签、不可成交保留分母，重叠日期不充独立样本。 |
| P1 基金与绩效 | 沿用 [基金研究](../../../docs/FUND_RESEARCH.md) 的确认净值、确认日、季报覆盖与待披露语义。显示模型净收益、证券子账户估算、已确认的真实现金流三个边界；股票与基金重叠暴露分层。 | 没有券商现金、费用、分红全量记录不报全账户精确收益；缺净值不当亏损。场内 ETF 按报价展示，场外按净值披露；不互用报价给对方填空。 |
| P1 Web 与 Agent | 现有驾驶舱首页按“先处置的持仓 → 左侧观察及变化 → 今日盘面与缺口”；进入个股看同批证据和单一失效条件。个人 Skill/CLI 查询同一只读结果，公开研究视图不可读个人持仓。代码已有的研究原文复核页按发布状态验收。 | 手机首屏、纯文本、网页、个人 CLI 对同一报告的个股数、动作和数据时点完全一致；未授权读不到报告；数值可重算不冒充论点已证实。 |
| P1 运行成本与恢复 | 日报从已落地数据生成；LLM 只润色，有截止时间，到时用确定性短句。沿用 DataHub 熔断和已有存档，首屏不依赖查慢接口；备援只接手未领取或有明确拒绝回执的部分。 | 记录日内最慢任务、外部调用/候选、故障恢复积压、应发/已接受/未知/漏发；恢复时间和客户端展示仅在有证据时报告。不因少数参考源失败阻断强制建议。 |

**复盘两个不同的问题。** 左侧研究问“在相同成本和风险下，有没有比现有策略更早发现且更值得跟踪的机会？”清仓日报问“提出退出后，相比继续持有，是否降低了风险，是否错过反弹？”分别保留未行动对照、被保护动作与反例。按行情状态、行业、是否超限切片，至少跨多批独立日期做滚动时间外验证；同日等预算、同一基准和 A 股执行规则（费用、滑点、T+1、停牌、涨跌停、部分成交），有完整可执行净收益证据才走原政策晋级门。仅价格标签、回填历史、一天表现或大模型评价均不调正式权重。

## 7. 参考项目与明确舍弃的做法

- 工作区内的 `daily_stock_analysis`（`9ab79b82`，`src/services/report_renderer.py`、`templates/report_brief.j2`）：参考短版报告和将市场状态放进解释的方式；Foliant 的持有人与未持有人必须区分，不复制固定买卖点。
- 工作区内的 `cls_ai_report`（`473edb0`，`src/cls_ai_report/pipeline.py`、`market_data.py`）：借鉴区分背景与增量时间窗、将新闻线索对应到有日期的行情；消息热度不能成为已确认的基本面事实。
- Shadow Life（`server/database/src/notification-worker.ts`）以稳定通知标识避免重复，Losna（`src/reminders.js`）区分中断在途与明确失败。借用状态处理，复用 Foliant 自己的渠道与加密存档，不引入新的通知服务。
- [Qlib 的工作流记录](https://qlib.readthedocs.io/en/stable/component/workflow.html)将实验输入和结果按运行留存；[Freqtrade 的前视偏差检查](https://www.freqtrade.io/en/stable/lookahead-analysis/)用切片重算观察信号是否改变。应用到左侧候选：在某个旧截止日截断全部输入重算，后来发布的财报或后续 K 线不得改变当时名单。不引入第三方交易引擎。

## 8. 实施顺序与退出条件

1. **P0：个股计数、账户新鲜度、清仓名单与送达。** 先跑只读回放与模拟渠道；真实自然日投递另验收。观察必报覆盖目标 100%（当日完整被指定渠道接受的应发日报份数 ÷ 当日应发日报份数；分母为 0 显示不适用，部分、未知、待核均不计入分子），明确漏发/未知数、重复接受数（目标 0）。降级复核单独计，不掩盖未完成报告。
2. **P1：通知与看盘。** 同时替换原生短版模板、网页/Skill 共用视图；首屏能读出时点、动作和原因。新旧按同一输入对照；检查大组合与最大正文、部分归档和失败恢复。若 renderer 回退，保留 P0 独立纯文本日报以及当天已有回执，不重复发。
3. **P1：左侧影子与复盘。** 冻结模板并积累前向证据；市场证据未绑批时只显示缺口，后补版本不能覆盖当时视图。达不到原研究门槛继续观察或退役；即使影子停用，原选股及清仓日报仍工作。是否上线由后续实施任务决定。
