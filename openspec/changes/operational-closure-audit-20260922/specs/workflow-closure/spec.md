# 运行闭环增量要求

## 新成交时间

系统 MUST 将没有时区的新成交输入解释为 Asia/Shanghai，将显式时区输入按实际时点换算。
同一时点的等价表示 MUST 得到一致指纹与排序；数据库会话时区 MUST NOT 改变新成交的时间。
历史记录 MUST NOT 被本次升级批量重写。

场景：输入 `2026-09-18 10:30:00`，数据库会话为 UTC。存储实际时点为 UTC 02:30，
Web/Agent 展示上海 10:30；以 `2026-09-18T02:30:00Z` 重试时不增加成交流水或持仓。

## 次日计划

系统 MUST 使用当日收盘本地 qfq 数据重新生成次日规则计划，保存实际生成时间和输入哈希。
缓存文件写入时间 MUST 位于当日收盘后至生成时刻之间；当天盘中缓存 MUST NOT 被当作收盘日线。
系统 MUST NOT 把新的持仓快照时间冒充旧计划的生成时间。读取 MUST 绑定同日同正式运行。
单股缺失 MUST 单独降级，MUST NOT 在读缓存失败时启动提供方调用或发送通知。

场景：正式候选带盘中旧计划，同时有 20:20 生成且当日日线完整的新计划。次日输出使用新计划，
当日复盘保留原止损触发依据；更换正式运行 ID 后旧重建快照失效。

## 参考源与后验质量

系统 MUST 拒绝以衍生指标、非有限数、非法日历日期、非 A 股代码或重复成员证明原策略完成。
系统 MUST 公开后验局部失败，MUST NOT 以外层任务 success 覆盖内部 partial。

场景：提供方重复返回同一只股票 20 次，不能证明 TOP5 完整；后验返回
`decision_loop=partial` 或 `external_err` 时，快照任务摘要显示 degraded。
