# 估值可用性与操作通知

系统 MUST 分开声明精确日期入库完成与当前正式选股可用性。
行情日期、财务、日历及覆盖准入 MUST 保持不变。估值宽限 MUST NOT 超过一个已确认交易日；
合格旧快照 MUST 保留真实日期、dataset IDs 与冻结政策。

## Scenario: 日线达标，估值晚到

- Given 当前行情覆盖 99.7%，当前估值 0 行，前一确认交易日估值覆盖超过 70%
- When 轻量补跑和正式选股执行
- Then 补跑成功并注明降级可用，正式选股允许执行，精确入库仍未完成
- And 后续补跑继续取当前估值，通知明确两个数据日期，manifest 可确定性回放。

## Scenario: 宽限不能替代门禁

- Given 估值过旧、质量不明、日期错位、覆盖不足，或日历不可信
- When 解析估值
- Then 不可用；无当日估值且无合格旧快照时任务按数据源未就绪跳过，不产生伪候选。

## Scenario: 加仓候选经过通知路由

- Given 加仓动作、五条减仓和八条加仓候选
- When 消息经过八行压缩后送达
- Then MUST 包含加仓候选及减仓风险，不能只包含减仓行。
- And 无合格加仓个股时 MUST 明确等待；冲突个股 MUST NOT 被同时建议买卖。
