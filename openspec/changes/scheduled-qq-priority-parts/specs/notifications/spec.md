# 定时报 QQ 通知增量要求

## 风险呈现

定时报 MUST 使用同批权威最终动作排序，先展示可执行风险动作，再展示硬风险观察、普通风险观察和选股。原始卖出被组合保护为 hold 时 MUST NOT 写成可执行卖出；非硬风险的受保护 hold SHOULD 按类别汇总，并明确风险未解除。

### 场景：尾部止损

输入顺序中最后一只持仓触及止损且执行证据不足时，输出 MUST 在普通风险观察和选股前逐只展示其代码、名称、核验现价、观察动作和真实短因。

## 完整分片

超过单条预算的报告 MUST 在一个 slot 批次内生成有序分片，并在领取 slot 前完成全部长度校验。每片 MUST 保留时间、序号及必要表头；关键行 MUST 实际进入一个分片，不得只报未展示数量。

### 场景：第二片拒绝

第一片被接受、第二片被拒绝时，后续分片 MUST 停止，批次 MUST 记为 partial 并保存接受数量。同槽重入 MUST 不重新发送已接受分片，也不得把批次标为 delivered。

## 存档

每片 MUST 通过既有受保护通知路由和加密存档，记录实际渠道正文与同一原稿的关联。只有全部 HTTP 接受且全部存档完成，整批回执的送达及存档状态才能为完整成功。
